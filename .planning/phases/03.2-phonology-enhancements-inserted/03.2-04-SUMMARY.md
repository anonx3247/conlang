**Fix 2 — romanize raw, not rewritten (commit `0bb1e7c`):**

Every caller of `WordGenerator.applyRewriteRules` was threaded to pair `(rawWord, phoneticWord)` where:
- `phoneticWord = applyRewriteRules(rawWord)` — used only for `[bracket]` display
- `rawWord` — used for `romanize()`, `validateWord()`, morphology engine input, and downstream tap handlers

Four panels fixed:

1. **`word_generator_panel.dart`** — `rawWords` + `phoneticWords` parallel lists, itemBuilder now passes `rawWord` to validateWord + romanize, and `phoneticWord` into `_WordRow` as the `word` field for the bracket display. Empty-state check now uses `rawWords.isEmpty`.

2. **`inspiration_panel.dart`** — added `romanizeProvider` watch. ListView pairs raw and phonetic, row display shows `romanize(rawWord)` as primary + `[phoneticWord]` bracket when the forms differ (or just phoneticWord when they're identical, preserving pre-fix behavior when no rewrite rules exist). **Critical**: `onWordSelected(rawWord)` now passes the phonemic form so `word_creation_form.dart`'s `romanize(ipa)` call at line 258 receives phonemic input, as expected.

3. **`morphology_preview_panel.dart`** — candidate filtering now validates phonotactics on raw forms (was: rewritten). ListView itemBuilder feeds the raw root into `engine.applyRule` (was: rewritten), producing a `derivedRaw`. Then `phoneticRoot = applyRewriteRules(root)` and `phoneticDerived = applyRewriteRules(derivedRaw)` are computed and passed to `_MorphWordRow` for the bracket display. Romanization uses `romanize(root)` and `romanize(derivedRaw)` — all phonemic.

4. **`preview_panel.dart`** — the debounced `_evaluate` method no longer applies rewrite rules at all during pipeline construction. `_PreviewRow.root` and `_PreviewRow.derived` are phonemic. `_buildRow` calls `gen.applyRewriteRules(row.derived)` and `gen.applyRewriteRules(row.root)` inline at render time using `ref.read` to get the current rewrite rules and inventory, producing the phonetic bracket display. The build method watches `parsedRewriteRulesProvider` so the panel refreshes when rules are edited without needing to re-run the debounced evaluation.

### Auto-fixed Issues

**2. [Rule 1 — UAT Bug] Rewrite rules were corrupting romanization across 4 panels**

- **Found during:** Human-verification checkpoint
- **Issue:** All four callers of `WordGenerator.applyRewriteRules` were mapping the raw generated word to a rewritten phonetic form and then passing that rewritten form to `romanize()`, `validateWord()`, the morphology engine, and (for `inspiration_panel`) the downstream `onWordSelected` tap handler. With rule `s -> z / V_V`, generated `/asa/` was becoming displayed+inserted as `aza` everywhere instead of retaining the correct romanization "asa" with a `[aza]` bracket.
- **Fix:** Threaded `(rawWord, phoneticWord)` pairs through all 4 panels. `romanize()`, `validateWord()`, morphology `applyRule`, and tap handlers all now operate on the phonemic form. Rewrite rules are applied only for the `[bracket]` display. Morphology preview panels also now apply rewrite rules AFTER morphology (not before), preserving affix concatenation against the phonemic token sequence.
- **Files modified:**
  - `lib/features/phonology/presentation/sound_rules/word_generator_panel.dart`
  - `lib/features/lexicon/presentation/dictionary/inspiration_panel.dart`
  - `lib/features/morphology/presentation/rules/morphology_preview_panel.dart`
  - `lib/features/morphology/presentation/rules/preview_panel.dart`
- **Tests added:**
  - `test/phonology/rewrite_rule_display_semantics_test.dart` (8 cases)
  - `test/lexicon/inspiration_panel_tap_test.dart` (2 cases)
  - `test/morphology_preview_raw_pipeline_test.dart` (3 cases)
- **Commit:** `0bb1e7c` — `fix(03.2-04): rewrite rules produce phonetic transcription only, not romanization (UAT feedback)`

**3. [Rule 2 — Reactivity improvement] `preview_panel.dart` now watches `parsedRewriteRulesProvider`**

- **Found during:** Fix 2 implementation
- **Issue:** After moving rewrite-rule application into `_buildRow` (which uses `ref.read`), edits to rewrite rules would not trigger a repaint of the preview panel's phonetic brackets. The debounced `_evaluate` pipeline was only triggered by `rule` changes, not rewrite-rule changes.
- **Fix:** Added `ref.watch(parsedRewriteRulesProvider)` at the top of `build` (value is intentionally discarded — the purpose is to register a subscription so Riverpod rebuilds the panel on rule changes).
- **Files modified:** `lib/features/morphology/presentation/rules/preview_panel.dart`
- **Commit:** `0bb1e7c` (bundled with Fix 2)
