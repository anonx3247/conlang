### WR-01: PreviewPanel does not re-evaluate when inventory, templates, or rewrite rules change

**Files modified:** `lib/features/morphology/presentation/rules/preview_panel.dart`
**Commit:** `278cea9`
**Applied fix:** Added `ref.listen` calls for `phonemeInventoryProvider`,
`parsedTemplatesProvider`, `parsedConstraintsProvider`, and
`parsedRewriteRulesProvider` inside `build()`. Each listener calls
`_scheduleRefresh()` when the corresponding upstream value changes, so
`_rows` is re-evaluated and root/derived/bracket columns stay consistent.
This matches the reviewer's "minimal patch" suggestion. Verified with
`dart analyze` (no issues) and `flutter test morphology_preview_raw_pipeline_test.dart`
(3/3 passing).

### WR-02: Stack-mode preview shows "no match" when rules fire but output equals input

**Files modified:** `lib/features/morphology/presentation/rules/preview_panel.dart`
**Commit:** `7bdaa10`
**Applied fix:** Introduced an `anySuccess` flag in the stack-mode loop that
tracks whether ANY rule produced a `MorphSuccess`. The `_PreviewRow` then
uses `anySuccess ? current : null` for `derived` and `anySuccess ? null :
'no match'` for `error`, so a chain where rule A transforms the form and
rule B reverts it (e.g. `a->e` then `e->a`) no longer reports "no match" —
it reports the final form with `rulesApplied > 0`, matching the single-rule
branch semantics.

Also removed the dead `break;` statement inside `case MorphNoMatch():`
(Dart 3 pattern switch cases do not fall through, so `break` only ends the
case and misleads readers into thinking it breaks the enclosing `for` loop).
The comment was updated to explicitly document the no-op semantics.

Verified with `dart analyze` (no issues) and
`flutter test morphology_preview_raw_pipeline_test.dart` (3/3 passing).

### WR-03: InspirationPanel regenerates words on every rebuild, not just on button press

**Files modified:** `lib/features/lexicon/presentation/dictionary/inspiration_panel.dart`
**Commit:** `1faa4b0`
**Applied fix:** Added memoization state to `_InspirationPanelState`:
`_cachedRawWords`, `_lastCacheKey`, and `_hasCacheKey`. In `build()`, a
cache key is computed via `Object.hash` over `_regenerateKey`,
`_minSyllables`, `_maxSyllables`, the template pattern strings, and the
consonant/vowel lists. `WordGenerator.generateWords` is only invoked when
the cache key changes or when the cache is empty, so incidental rebuilds
(from slider drags that don't trigger local `setState`, parent rebuilds,
or `romanize`/`parsedRewriteRulesProvider` updates) no longer regenerate a
fresh candidate list — only explicit refresh-button presses or actual
input changes do.

The `// ignore: unused_local_variable` dance (`final _ = _regenerateKey;`)
was also removed — the new cache-key approach references `_regenerateKey`
directly as part of the hash, making the lint suppression unnecessary. This
incidentally resolves IN-01 as well, though IN-01 was out of scope for this
fix run.

Rewrite rules are deliberately NOT part of the cache key: they only affect
the displayed phonetic bracket, not the raw phonemic candidates. A rewrite
rule edit causes a rebuild (because `rewriteRules` is watched) but the
cached raw list is reused and only the `applyRewriteRules` output changes.

Note: The same pattern exists in `word_generator_panel.dart` and
`morphology_preview_panel.dart`. The reviewer flagged these as potentially
intentional ("Regenerate words" tooltip semantics). They were not touched
in this fix run — if regeneration-on-rebuild is intentional there, a
comment documenting the design would help future readers. This is out of
scope for the Warning-level fix pass.

Verified with `dart analyze` (no issues) and
`flutter test test/lexicon/inspiration_panel_tap_test.dart` (2/2 passing,
both the raw-form-on-tap and phonetic-bracket-display regression tests).
