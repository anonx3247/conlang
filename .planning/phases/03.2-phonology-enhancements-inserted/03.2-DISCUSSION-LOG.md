## Gray area selection

Claude initially identified 6 gray areas; after a failed 6-option AskUserQuestion call, Claude presented 4 load-bearing ones:

| Option | Description | Selected |
|--------|-------------|----------|
| Schema for out-of-inventory sounds | PHON-09 requires classes to include sounds not in the project's phoneme table. Current schema stores int FKs only. | (bypassed by scope narrowing) |
| Sharing mechanism across projects | PHON-10 requires shareable classes. No global DB exists. | (dropped — scope removed) |
| Allophone computation strategy | PHON-11 needs rule transformation. Rules parse but don't apply. | (addressed in follow-up) |
| Allophone viewer UI + trigger | Where the view appears on phoneme click. | (addressed in follow-up) |

**User's choice:** User responded with a scope-collapsing statement rather than picking from the list:
> "All i wanted to discuss was to say we can greatly simplify this: I don't want shareable or cross-project classes. Just make new default classes that contain phonemes that may not be in the inventory (e.g. nasal, rhotic, stop, liquid). I want to see the allophones"

**Notes:** This collapsed PHON-10 out of scope entirely and implicitly resolved the schema gray area (no DB change needed — defaults can be hardcoded in Dart). Remaining decisions were captured via a second focused batch.

**User's choice (free text / Other):**
> "both in the popover of the phoneme, and next to it in the charts when holding alt (since alt shows the phoneme instead of its romanization)"
