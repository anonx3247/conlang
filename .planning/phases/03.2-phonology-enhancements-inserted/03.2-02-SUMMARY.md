# Phase 03.2 Plan 02: Alias resolution in DSL consumers + PHON-09 end-to-end proof

**Single-letter aliases S/N/F/L/R now resolve to the predefined default lists in both DSL class resolvers via a case-sensitive lookup that runs before the lowercased map fall-through, with a matching validator that reserves those names at the entry point and an end-to-end test proving `[stop]V` draws from defaults against a user inventory with zero consonants.**

## Accomplishments

- `WordGenerator._resolveClass` and `morphology_engine.resolvePhonemeClass` now both perform a case-sensitive lookup against `defaultNaturalClassAliases` between the C/V switch and the lowercased-map fallback, so `S` → default 13 stops, `N` → default 7 nasals, etc., WITHOUT ever shadowing a literal `/s/` phoneme (the lowercase falls through to tier-3 lookup untouched)
- Parity between the two resolvers is enforced mechanically by a `bothReturn` test helper — every assertion in `resolve_class_test.dart` runs both functions and compares their outputs to each other AND to the expected list, so any future drift between the two implementations fails a test at the test-file level
- `@visibleForTesting` `resolveClassForTesting` wrapper added to `WordGenerator` so unit tests can exercise the private `_resolveClass` method directly without going through `generateWords`
- `validateNaturalClassName` extracted as a pure top-level function in `natural_class_editor.dart` and wired into the existing `TextFormField.validator`; rejects C/V/S/N/F/L/R with alias-expansion error messages identifying which default class each letter reserves
- Lowercase full names (`stop`, `nasal`, `fricative`, ...) are INTENTIONALLY still accepted by the validator — D-06 lets users shadow default full-name classes with their own member lists, so only single-letter aliases are reserved
- 28 new phonology tests (11 resolver + 14 validator + 3 end-to-end DSL) all green; full phonology + morphology + lexicon suite (129 tests) green; `flutter analyze` clean on all 6 modified files
- End-to-end PHON-09 success proof landed: `parseSyllableTemplate('[stop]V')` + `buildInventory([], vowels, [])` + `WordGenerator().generateWords(count: 20)` produces 20 words, each starting with a character from the default `_stops` list. The `SV` alias-path variant produces the same result via the case-sensitive alias check. A third test asserts `defaultNaturalClasses['stop']` and `defaultNaturalClassAliases['S']` point to the same list, catching any future drift in Plan 01's data

## Decisions Made

- **Alias check placement (tier 2 of 4)** — Between the C/V system switch (tier 1) and the lowercased map lookup (tier 3). This preserves all existing Phase 1 behavior, inserts the new case-sensitive alias semantics without disturbing the lowercase path, and keeps the exact-case fallback (tier 4) as a legacy edge-case safety net.
- **Parity via test helper, not shared code** — The two resolvers are in different files and serve different call sites (one is a private method on `WordGenerator`, the other is a top-level function consumed by the morphology engine). Rather than extract a shared helper and introduce a new dependency direction, the parity is enforced by the `bothReturn` test that runs both and compares their outputs byte-for-byte. This is explicitly documented in both resolvers' doc comments so future editors know to update both and keep the parity test passing.
- **Pure-function validator refactor** — Lifted the validator out of the widget closure and into a top-level `validateNaturalClassName` function. This is MUCH simpler to unit-test than pumping a `Form` + `TextFormField` + entering text via `WidgetTester`, avoids any Riverpod setup, and the function is still referenced by the widget via `validator: validateNaturalClassName` so the production path is unchanged.
- **D-06 allows lowercase full-name shadowing** — The validator intentionally does NOT reject `stop`, `nasal`, `fricative`, etc. Users who want to define their own `stop` class with only 3 segments should be allowed to do so, and `buildInventory`'s defaults-then-user-overlay merge (from Plan 01) correctly lets the user list win. Only the single-letter aliases are reserved, because those would otherwise create an invisible collision: the alias map is checked BEFORE the user map, so a user class named `S` could never be reached.
- **End-to-end test uses minimal Phoneme fixture** — Verified the Drift generated `Phoneme` constructor (lib/db/app_database.g.dart lines 263-285) only requires `id`, `symbol`, `type`; all other fields are nullable. No need for the `_vowel` helper fallback documented in the plan's degradation path — the Drift-row construction was straightforward and matches the pattern already in use in `build_inventory_test.dart`.
- **Drift parity guard test** — Added a third end-to-end test (`[stop]V and SV produce results drawn from the same list`) asserting `defaultNaturalClasses['stop']` equals `defaultNaturalClassAliases['S']`. Plan 01 happens to keep these in sync (both point to the `_stops` const list), but this test prevents any future edit from silently decoupling them — it would break the alias path's behavior relative to the full-name path.
