## Warnings

### WR-01: PreviewPanel does not re-evaluate when inventory, templates, or rewrite rules change

**File:** `lib/features/morphology/presentation/rules/preview_panel.dart:38-44`, `lib/features/morphology/presentation/rules/preview_panel.dart:58-62`

**Issue:** `_evaluate()` is only scheduled from `initState`, `didUpdateWidget` (when `widget.rule` changes), the stack-mode toggle, and the manual refresh button. It is NOT re-scheduled when the phoneme inventory, templates, constraints, or parsed rewrite rules change upstream. The `build()` method does call `ref.watch(parsedRewriteRulesProvider)` (line 232), which causes the widget to rebuild, but `_rows` still contains the morphology output computed against a stale inventory/constraint snapshot.

Concretely: if the user opens the rule editor, generates a preview, then switches to the phonology tab and adds a new phoneme or edits a phonotactic template, the preview will keep showing rows derived from the old inventory while `_buildRow` (line 334-345) recomputes the `[bracket]` phonetic transcription against the NEW inventory/rewrite rules. This produces visibly inconsistent rows: `root` and `derived` come from the old snapshot, but the bracket transcription and romanization come from the new snapshot.

**Fix:** Watch the upstream providers inside `build()` and trigger `_scheduleRefresh()` when they change, or (cleaner) convert `_rows` into a derived value recomputed during `build()` rather than cached state. Minimal patch:

```dart
@override
Widget build(BuildContext context) {
  // ...
  final inventory = ref.watch(phonemeInventoryProvider);
  final templates = ref.watch(parsedTemplatesProvider);
  final constraints = ref.watch(parsedConstraintsProvider);
  ref.watch(parsedRewriteRulesProvider);

  // Re-evaluate if upstream inputs changed since last _evaluate().
  ref.listen(phonemeInventoryProvider, (_, __) => _scheduleRefresh());
  ref.listen(parsedTemplatesProvider, (_, __) => _scheduleRefresh());
  ref.listen(parsedConstraintsProvider, (_, __) => _scheduleRefresh());
  // ...
}
```

### WR-02: Stack-mode preview shows "no match" when rules fire but output equals input

**File:** `lib/features/morphology/presentation/rules/preview_panel.dart:172-178`

**Issue:** In stack mode, the row flags "no match" via `current == word ? 'no match' : null`. But `rulesApplied` may be non-zero if at least one rule fired and then a subsequent rule reverted the form (e.g. rule A: `a -> e`, rule B: `e -> a`). The user sees "no match" even though rules applied, while the single-rule mode uses the engine's `MorphSuccess`/`MorphNoMatch` result directly. This is a silent display inconsistency between the two modes.

Also, the `break` inside `case MorphNoMatch():` (line 156-159) is a no-op in Dart 3 pattern switches and does NOT break out of the enclosing `for` loop — it just ends the case. The comment "Skip rules that don't match; continue with current form" is correct behavior but the `break` is misleading to readers; it reads like a loop break.

**Fix:**

```dart
// Track whether any rule produced a successful MorphSuccess, independent
// of whether the form eventually coincided with `word`.
var anySuccess = false;
for (final r in orderedRules) {
  final result = engine.applyRule(r, current, inventory);
  switch (result) {
    case MorphSuccess(:final form):
      current = form;
      rulesApplied++;
      anySuccess = true;
    case MorphNoMatch():
      // fall through — continue with current form
  }
}

rows.add(_PreviewRow(
  root: word,
  derived: anySuccess ? current : null,
  error: anySuccess ? null : 'no match',
  violations: validation,
  rulesApplied: rulesApplied,
  stackMode: true,
));
```

Also drop the `break;` statements inside both switch cases — they are dead statements under Dart 3 switch semantics.

### WR-03: InspirationPanel regenerates words on every rebuild, not just on button press

**File:** `lib/features/lexicon/presentation/dictionary/inspiration_panel.dart:49-72`

**Issue:** `WordGenerator()` is constructed with a fresh `Random()` on every `build()` call (line 58) and `generateWords` is called unconditionally. This means any state change in the widget tree (a slider drag that doesn't trigger local `setState`, a parent rebuild, a provider update for `romanize`/`parsedRewriteRulesProvider`, etc.) will produce a completely new list of candidate words — causing UI flicker and losing whatever words the user was looking at.

The `_regenerateKey` + `// ignore: unused_local_variable` dance at lines 49-51 is a workaround, but it's backwards: the regenerate KEY exists to keep the rebuild honest, but there is no memoization, so EVERY rebuild regenerates. The intended behavior per the refresh-button tooltip ("Regenerate") is that candidates persist across incidental rebuilds and only change on explicit refresh.

**Fix:** Memoize `rawWords` against the inputs that should cause a regeneration (template list, inventory, syllable range, regenerate key). One option:

```dart
List<String>? _cachedRaw;
int _lastKey = -1;

// Inside build, after gathering inputs:
final cacheKey = Object.hash(
  _regenerateKey,
  _minSyllables,
  _maxSyllables,
  Object.hashAll(templates),
  Object.hashAll(inventory.consonants),
  Object.hashAll(inventory.vowels),
);
if (cacheKey != _lastKey || _cachedRaw == null) {
  _cachedRaw = gen.generateWords(
    templates: templates,
    inventory: inventory,
    count: 12,
    minSyllables: _minSyllables,
    maxSyllables: _maxSyllables,
  );
  _lastKey = cacheKey;
}
final rawWords = _cachedRaw!;
```

Note: the same pattern applies to `word_generator_panel.dart` and `morphology_preview_panel.dart`, which also regenerate on every rebuild. If intentional (the tooltip does say "Regenerate words"), consider adding a comment documenting the design, or the current infinite-regeneration behavior will look like a bug to future readers.

### IN-01: Unused-local-variable dance in `inspiration_panel.dart`

**File:** `lib/features/lexicon/presentation/dictionary/inspiration_panel.dart:49-51`

**Issue:**
```dart
// ignore: unused_local_variable
final _ = _regenerateKey;
```
This pattern references `_regenerateKey` only to suppress a lint. It's cryptic to readers and the comment on line 49 ("Rebuild _words whenever _regenerateKey changes") is misleading since `_words` is not a cached field. Dart also treats `_` as a "wildcard" identifier in recent versions, which can generate additional warnings.

**Fix:** Either (a) remove the line entirely — `setState` already triggers a rebuild, so no reference is needed — or (b) actually cache regeneration behind `_regenerateKey` (see WR-03). Prefer (b) because it fixes the underlying flicker.

### IN-02: Feature-bundle detection allows empty `[]` output

**File:** `lib/features/phonology/domain/allophone_computer.dart:113-117`

**Issue:** The doc comment says "Guards against lone `[` or `]` malformed outputs" and "with at least one character between", but the condition is:
```dart
final isBundle = r.output.length >= 2 &&
    r.output.startsWith('[') &&
    r.output.endsWith(']');
```
A literal `[]` output (length 2) passes the check despite having zero characters between the brackets. Not a crash risk, but inconsistent with the doc.

**Fix:** Change `>= 2` to `>= 3` to match the comment, or update the comment to say "length at least 2".

### IN-03: `applyAblaut` crashes on negative `count`

**File:** `lib/features/morphology/domain/morphology_engine.dart:364-386`

**Issue:** `matchIndices.take(count)` throws `RangeError` if `count` is negative. The DSL parser presumably constrains `count` to a positive integer, but there is no explicit guard in the engine and no test for `count == 0` or negative values. If a future parser change allows `0` or negative, the engine will silently replace nothing (for 0) or crash (for negative).

**Fix:** Clamp at the top of `applyAblaut`:

```dart
if (count != null && count <= 0) return root;
```

### IN-04: Empty-literal parse fallback in `_parsePattern` can silently drop characters

**File:** `lib/features/morphology/domain/morphology_engine.dart:146-167`

**Issue:** When `[` or `(` has no matching close bracket, the code does `segments.add(_LiteralSegment(s.substring(i)))` and `break`, which converts the rest of the pattern (including the unmatched bracket) into a literal. The parser upstream likely rejects malformed patterns, but this fallback is a silent behavior change if a pattern ever reaches this function unvalidated. Consider logging a debug warning or returning an error sentinel instead of silently rewriting.

**Fix:** Lowest-effort: add a `debugPrint` or `assert`:

```dart
if (close == -1) {
  assert(false, 'Malformed pattern "$pattern" reached _parsePattern without upstream validation');
  segments.add(_LiteralSegment(s.substring(i)));
  break;
}
```

### IN-05: `applyRedup` scope `CV` falls back to full root on empty match

**File:** `lib/features/morphology/domain/morphology_engine.dart:440-445`

**Issue:** When `scope == 'CV'` but the root has only vowels (no consonant) or only one consonant with no following vowel, `redupPart` ends up empty, and the code silently substitutes the entire root. This is documented as a "fallback", but the behavior is surprising: a user specifying `CV` reduplication probably does not want full-root reduplication when the root has no CV sequence. Consider either documenting the fallback in the DSL reference or returning the root unchanged.

**Fix:** Decide on intentional behavior and document:

```dart
if (redupPart.isEmpty) {
  // Fallback: no CV sequence found → reduplicate full root.
  // Alternative: return root unchanged. Behavior locked by PHON-XX test.
  redupPart = root;
}
```

### IN-06: Dead `break` statements in Dart 3 pattern switch

**File:** `lib/features/morphology/presentation/rules/preview_panel.dart:156-159`

**Issue:** In Dart 3 pattern switches, cases do NOT fall through and do NOT need explicit `break`. The `break` inside `case MorphNoMatch(): break;` is dead code and misleads readers into thinking it breaks the enclosing `for` loop (it doesn't — it just ends the case, and the loop body then resumes with the next iteration normally).

**Fix:** Remove the `break` or replace with a one-line comment:

```dart
case MorphNoMatch():
  // no-op: continue with current form
```

Same pattern may appear in other files that use `switch (result) { case MorphSuccess(...): ...; case MorphNoMatch(): break; }` — audit morphology_preview_panel.dart around line 167-171 (appears to use `if case` pattern instead, which is fine).
