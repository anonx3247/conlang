## Spacing Scale

Declared values (multiples of 4). Source: existing widget patterns in `paradigm_table_widget.dart`, `construction_preview.dart`, `cell_override_dialog.dart`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge offsets, chip padding |
| sm | 8px | Between cell lines (rom → IPA gap), within dialog sections |
| md | 16px | Container internal padding (`EdgeInsets.all(16)`), dialog content padding |
| lg | 24px | Section breaks within dialogs |
| xl | 32px | Dialog inset vertical |
| dialog-inset | 40px | Dialog inset horizontal — inherited from existing `RuleEditorDialog` (`EdgeInsets.symmetric(horizontal: 40, vertical: 32)`); not a new design choice |
| 2xl | 48px | Reserved — not used in this phase |
| 3xl | 64px | Reserved — not used in this phase |

Exceptions:
- Paradigm cell vertical padding: `EdgeInsets.symmetric(vertical: 4, horizontal: 4)` (token xs) — preserves existing cell density
- Rule editor dialog inset: `EdgeInsets.symmetric(horizontal: 40, vertical: 32)` — horizontal 40px is the `dialog-inset` token above, sourced from existing `RuleEditorDialog`; vertical 32px maps to token xl
- Touch targets for delete/icon buttons: 44px minimum (Material 3 default tap area)

## Component Inventory

### New: ParadigmConstructionFilled cell variant

Renders inside the existing `paradigm_table_widget.dart` cell builder. Follows two-line layout identical to `ParadigmFilled`:

```
[romanized form]          ← bodyMedium, weight 400, ViolationText
[IPA form]                ← bodySmall, cs.onSurface alpha 0.6
```

**Construction badge:** Small chip/badge in top-right of cell.
- Shape: `RoundedRectangleBorder(radius: 4px)`
- Background: `cs.primaryContainer`
- Icon: `Icons.account_tree_outlined` at 10px (construction = phrase tree)
- Text: none (icon only to preserve cell density)
- Tooltip: `"Analytically realized via [construction name]"` — shown on hover after 500ms (matches app `waitDuration`)

### New: ParadigmUnresolvable cell variant

```
[!]  Cycle detected        ← Icons.sync_problem (16px, cs.error) + bodySmall text
```

- Cell background: `cs.errorContainer.withValues(alpha: 0.15)`
- Border: `Border.all(color: cs.error.withValues(alpha: 0.4), width: 0.5)`
- Tooltip body: full cycle path string, e.g. `"Cell FUT → Cell COND → Cell FUT"` — source: CONTEXT.md D-09
- No click action (cell is inert when unresolvable)

### Modified: RuleEditorDialog — rule type selector

New `SegmentedButton` or `DropdownButton` at top of form to select rule type. Three values:

| Label | Kind | When shown |
|-------|------|------------|
| Inflectional | `RuleKind.inflectional` | Always (existing behavior) |
| Derivational | `RuleKind.derivational` | Always (existing behavior) |
| Construction | `RuleKind.construction` | Always (new kind) |

When **Construction** is selected, the DSL text field and branch editor are replaced with:
1. **Construction picker** — `DropdownButton<int>` listing all defined constructions by name
2. **Word slot selector** — `DropdownButton<int>` listing slots in the selected construction, user picks which slot is the "word slot"
3. **Form reference picker** — Two radio options:
   - "Base/uninflected root form" (default)
   - "Reference another paradigm cell" → shows a second dropdown listing all dimension levels as `{DimName}: {LevelName}` for cell cross-reference

Feature-binding chips (POS + dimension chips) remain identical to inflectional mode.

### Modified: CellOverrideDialog

No structural changes. The existing "Create a rule for this cell" shortcut remains. No new controls needed — per-word construction suppression is handled at the rule-editor level (D-03, D-13).

## Interaction Contracts

### Paradigm cell click (ruleEditor mode)

| Cell type | Click action |
|-----------|-------------|
| `ParadigmConstructionFilled` | Opens `RuleEditorDialog` with construction rule pre-loaded for edit |
| `ParadigmUnresolvable` | No action (inert). Tooltip explains cycle path on hover |
| `ParadigmFilled`, `ParadigmUncovered`, `ParadigmUnmarked` | Existing behavior unchanged |

### Construction picker in rule editor

- Dropdown is empty state if no constructions are defined → shows disabled state with hint text: `"No constructions defined. Add one in Grammar → Constructions."`
- Selecting a construction immediately populates the word slot dropdown with that construction's slots
- Word slot dropdown defaults to the first slot of type `pos` (the most common word-slot type)

### Form reference: cell cross-reference

- Cross-reference picker lists all `{DimName}: {LevelName}` combinations for the current POS
- Selecting a cell reference that would create a cycle is not blocked at the UI layer — the cycle detector runs at resolution time and surfaces `ParadigmUnresolvable` (D-09)

## Phase-Specific Notes

### Why no shadcn gate
Project is Flutter/Dart (desktop), not React/Next.js/Vite. shadcn is not applicable. Design system is Flutter Material 3 with the theme defined in `lib/app.dart`.

### Design consistency constraints
- All new cells MUST fit within the existing cell container width without overflow. The construction badge MUST be an overlay (positioned `Stack` child) not an additional layout child, to preserve column widths.
- `ParadigmUnresolvable` cells MUST render at the same fixed height as `ParadigmFilled` cells to prevent paradigm table row height jitter.
- The rule-type selector in `RuleEditorDialog` MUST not change the dialog minimum width. Existing dialog width is constrained by `Dialog(insetPadding: EdgeInsets.symmetric(horizontal: 40, vertical: 32))`.
