## Tests

### 1. Construction rules section visible in InflectionalRulesPage
expected: |
  Open Grammar → Inflectional Rules for any POS. Below the existing inflectional rules list you should see a "CONSTRUCTION RULES" section header and a "New Construction Rule" text button. If no construction rules exist yet, you see the empty state: "No construction rules for this POS. Click a paradigm cell or use New Rule."
result: pass
note: initially failed (InflectionalRulesPage not wired into InflectionsPage); fixed inline in commit 210ba1a

### 2. Create a construction rule
expected: |
  Tap "New Construction Rule". A dialog opens with: rule name field, POS + feature binding chips (same as inflectional editor), a Construction dropdown, a Word Slot dropdown, and a "Base form / Reference another cell" radio picker. Fill in a name, pick a construction, pick a word slot, leave it on base form, tap Save. The new rule card appears in the CONSTRUCTION RULES section with a tree-icon (🌲) badge.
result: pass

### 3. Edit an existing construction rule
expected: |
  Tap a construction rule card in the list. The editor dialog reopens with all fields pre-populated: name, POS chips selected, construction chosen, word slot chosen, and form reference set to whichever option was saved. Making a change and tapping Save updates the card in the list.
result: pass

### 4. Delete a construction rule
expected: |
  Open an existing construction rule in the editor dialog. A trash/delete icon is visible in the dialog (no confirm prompt — it deletes immediately). Tapping it closes the dialog and the rule disappears from the CONSTRUCTION RULES list.
result: pass
note: initially missing inline icons on card; fixed to add pencil + trash icons matching inflectional rules pattern (commit dfb1e31)

### 5. Paradigm cell: ConstructionFilled rendering
expected: |
  Navigate to the paradigm viewer for a lexeme whose POS has an active construction rule that matches a cell's feature set. The matched cell should show two lines (romanization on top, IPA in brackets below) — same layout as a normal filled cell — plus a small tree-icon badge in the top-right corner of the cell. Hovering/long-pressing the badge shows a tooltip: "Analytically realized via [rule name]".
result: pass

### 6. ConstructionFilled cell click opens rule editor
expected: |
  Tap a construction-realized cell (the one with the tree badge). The RuleEditorDialog opens in construction mode, pre-populated with the matching construction rule (name, construction, word slot, form reference all filled in). You can edit and save from there.
result: pass

### 7. Paradigm cell: Unresolvable (cycle detected) rendering
expected: |
  If a construction rule creates a circular reference (e.g. cell A's form reference points to cell B which points back to cell A), the affected cell(s) render with a reddish/error background, a warning icon, and the text "Cycle detected". Hovering/long-pressing shows a tooltip with the cycle path (e.g. "Circular dependency: Cell FUT → Cell COND → Cell FUT"). The cell is inert — tapping it does nothing.
result: pass
note: two bugs fixed inline — cell ref dropdown now shows full Cartesian product (7eb197d) and stale initialValue crash fixed (9e888d5)

### 8. Base form reference resolves to uninflected form
expected: |
  Create a construction rule with form reference = "Base (uninflected) form". In the paradigm viewer, a matched cell should show the base/uninflected word form composed with the particle(s) from the construction, not an inflected form.
result: pass

### 9. Cell cross-reference resolves to another cell's form
expected: |
  Create a construction rule with form reference = "Reference another cell", then pick a specific dimension/level cell from the dropdown. In the paradigm viewer, the matched cell should show the form from the referenced cell (the target cell's IPA/rom) composed with the construction's particles. If the referenced cell itself is an ordinary inflected form, that inflected form should appear in the composed output.
result: pass
