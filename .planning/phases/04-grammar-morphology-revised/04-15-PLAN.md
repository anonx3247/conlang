    **Subtask 1a — D-78 shared pure notation helpers (MUST happen before the bijection validator below).**

    Create a new file `lib/features/phonology/domain/notation_helpers.dart`. This file has NO Riverpod imports, NO Flutter imports, and NO database imports — it is pure Dart so the v10 migration in Task 3 can reuse it without a WidgetRef. Export:

    ```dart
    /// A single row of the romanization mapping, in the shape needed by
    /// notation_helpers. Both the runtime RomanizationMapping rows and the
    /// raw QueryRow results the v10 migration reads can be projected to this
    /// tiny record.
    typedef NotationMapping = ({String ipaSymbol, String latinMapping});

    /// Segment a phonemic IPA string into its constituent phonemes using a
    /// longest-IPA-first left-to-right walk over [mappings]. Characters that
    /// match no mapping are emitted as single-code-point segments so class-ref
    /// tokens and structural characters flow through unchanged.
    List<String> phonemicSegmentation(String phonemic, List<NotationMapping> mappings);

    /// Convert rom → phonemic. Treats `.` as a consumed glyph separator
    /// (emits nothing, resets the longest-match scan). Everything else is
    /// longest-latin-first left-to-right substitution. Characters that match
    /// no mapping are passed through verbatim.
    String dotAwareDeromanize(String rom, List<NotationMapping> mappings);

    /// Convert phonemic → rom. Segments [phonemic] via [phonemicSegmentation],
    /// emits the rom form of each segment in order, and inserts `.` between
    /// two adjacent rom tokens whenever the naïve concatenation of their
    /// rom forms would re-parse (via [dotAwareDeromanize] on the pair in
    /// isolation) as a DIFFERENT phoneme sequence than `[segment_i, segment_{i+1}]`.
    /// This is the D-78 boundary-insertion algorithm.
    String smartRomanize(String phonemic, List<NotationMapping> mappings);

    /// Return true iff every phoneme sequence representable via [mappings]
    /// round-trips: dotAwareDeromanize(smartRomanize(x)) == x. Used by the
    /// D-72 bijection validator's nonRoundTrip check. This replaces the
    /// previous "each rom literal must round-trip" check with a sequence-
    /// level check that accepts dot-disambiguatable mapping sets.
    bool isDotAwareBijection(List<NotationMapping> mappings);
    ```

    Boundary insertion detail: for each pair `(r_i, r_{i+1})` where `r_i = romOf(segment_i)` and `r_{i+1} = romOf(segment_{i+1})`, compute `dotAwareDeromanize(r_i + r_{i+1})`. If that equals `segment_i + segment_{i+1}` (as a concatenated string), emit no separator; otherwise emit `.` before writing `r_{i+1}`. This algorithm is O(n * max_rom_length) and runs during each smartRomanize call; it is cheap enough for per-keystroke use and for the v10 migration over hundreds of rules.

    `isDotAwareBijection` implementation: scan the active mapping set for the duplicate-target cases (these cannot be dot-disambiguated and return false immediately), then for every phoneme `p` in the mapping domain and every ADJACENT pair `(p, q)` in the mapping domain, assert `dotAwareDeromanize(smartRomanize(p + q)) == p + q`. Document in a comment that the exhaustive pairwise test is sufficient because dot boundary decisions are local (each boundary decision only depends on its two adjacent segments).
