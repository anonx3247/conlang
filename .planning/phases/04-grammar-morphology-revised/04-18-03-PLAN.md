**Issue 37a — Hard check rejects 1-dim POSes:**

In `_buildSingleParadigmTable` (line ~105) and `_buildStackedIntrinsicSlices` (line ~249), there's a hard check `if (dims.length < 2)` / `if (nonIntrinsicDims.length < 2)` that shows an error message. A POS with 1 non-intrinsic dimension should render a single-row table.

Fix for `_buildSingleParadigmTable`:
1. Replace the `if (dims.length < 2)` guard. When `dims.length == 1`, render a single-row table where the one dimension provides the column headers and there's only one data row.
2. The existing `_buildTable` method likely expects a row dimension and a column dimension. For 1-dim, pass the single dimension as columns and use a trivial "base form" as the single row, OR use a flat horizontal layout: one cell per level of the single dimension.
3. Look at how `_buildTable` works — if it takes `rowDim` and `colDim` parameters, for 1-dim pass null for rowDim and the single dim as colDim. If `_buildTable` can't handle null rowDim, create a `_buildSingleDimTable` helper that renders a simple Row/Table with one row.

Fix for `_buildStackedIntrinsicSlices`:
1. Same fix: when `nonIntrinsicDims.length == 1`, render a single-row table per intrinsic slice instead of rejecting.
2. When `nonIntrinsicDims.length == 0` (all dims are intrinsic), show a simple "base form" display — just the root word, since there are no non-intrinsic axes to generate a paradigm from.

**Issue 37b + 39b — Word detail paradigm shows all-word dropdowns instead of filtering to that word:**

In `_buildStackedIntrinsicSlices`, when `lexemeId != null` (i.e., rendering for a specific word in word detail), the widget should:
1. NOT show intrinsic combination dropdowns
2. Instead, determine the word's own intrinsic levels from its `intrinsicLevelsJson`
3. Render ONLY the slice matching that word's intrinsic combination

Implementation:
1. In `_buildStackedIntrinsicSlices`, check if `widget.lexemeId != null` (or the equivalent since it's a ConsumerWidget — check constructor).
2. If a specific lexeme is provided:
   a. Watch the lexeme to get its `intrinsicLevelsJson`
   b. Decode to `Map<int, int>` using `IntrinsicLevelsCodec.decode`
   c. Build ONE combination from the word's intrinsic levels
   d. Render a single `_IntrinsicSliceSection` for just that combination, using `[lexeme]` as the pool
   e. Skip the intrinsic combination loop entirely
3. If no specific lexeme (template mode / grammar tab): keep current behavior of showing all combinations with dropdowns.

This also fixes 39b (word-detail paradigm shows all intrinsic slices) since it's the same root cause.

**Issue 37c — Grammar tab needs multi-word selection for intrinsic levels:**

Currently `inflections_page.dart` has a single `_selectedLexemeId` and a `DropdownButton<int?>` for word selection. For POSes with intrinsic dimensions, the user wants to select MULTIPLE words (one per intrinsic level) to display all intrinsic slices side by side.

Fix in `inflections_page.dart`:

1. Add a new state field: `Set<int> _selectedLexemeIds = {};` alongside the existing `_selectedLexemeId`.
2. Detect whether the selected POS has intrinsic dimensions:
   ```dart
   final dimsAsync = ref.watch(dimensionsForPosProvider(_selectedPosId!));
   final dims = dimsAsync.asData?.value ?? const <Dimension>[];
   final hasIntrinsic = dims.any((d) => d.intrinsic);
   ```
3. When `hasIntrinsic`:
   a. Replace the single `DropdownButton` with a multi-select widget. Use Flutter's `FilterChip` or `ChoiceChip` list pattern:
      - Show a Wrap of FilterChips, one per eligible word (filtered to selected POS)
      - Each chip is selected/unselected based on `_selectedLexemeIds.contains(lexeme.id)`
      - Tapping toggles the word in/out of the set
   b. Pass the selected lexeme IDs to `ParadigmTableWidget` via a new optional parameter `lexemeIds`
4. When NOT `hasIntrinsic`: keep the existing single-select dropdown (no change).

Fix in `paradigm_table_widget.dart`:

1. Add an optional `List<int>? lexemeIds` parameter to `ParadigmTableWidget` constructor.
2. In `_buildStackedIntrinsicSlices`, when `lexemeIds` is provided and non-empty:
   a. For each intrinsic combination section, filter the lexeme pool to only include lexemes whose IDs are in `lexemeIds`
   b. Skip combinations that have no matching lexeme in the pool
   c. This naturally shows only the intrinsic slices the user selected
3. When `lexemeIds` is null/empty and `lexemeId` is also null: show all combinations (current template behavior).

The multi-select approach lets users pick one word per gender (e.g., "sana" for Feminine, "kato" for Masculine) and see both paradigm slices rendered.
