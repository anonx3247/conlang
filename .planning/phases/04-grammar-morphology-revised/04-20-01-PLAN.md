When a derivational rule has an output POS that has intrinsic dimensions (e.g., Noun with Gender[M/F/N]), the user needs to specify which intrinsic level the output word gets. Currently only Input POS and Output POS dropdowns exist in derivational mode.

**Add state field:**
1. Add a new state field `Map<int, int> _outputIntrinsicLevels = {};` — keyed by dimension ID, valued by level ID. This maps each intrinsic dimension of the output POS to the selected level.

**Add UI:**
2. In the derivational mode section of `build()` (find the area where `_inputPosId` and `_outputPosId` dropdowns are rendered — search for `_outputPosId` dropdown widget), add BELOW the Output POS dropdown:
   - Watch `dimensionsForPosProvider(_outputPosId!)` when `_outputPosId != null`
   - Filter to only intrinsic dimensions: `dims.where((d) => d.isIntrinsic)`
   - For each intrinsic dimension, render a Row with:
     - Label: dimension name (e.g., "Gender")
     - A `DropdownButton<int>` listing the dimension's decoded levels (use `decodeLevelsJson(dim.levelsJson)`)
     - Selected value from `_outputIntrinsicLevels[dim.id]`
     - onChanged: update `_outputIntrinsicLevels[dim.id] = value`
   - If no intrinsic dims exist for the output POS, render nothing

**Wire to save:**
3. In the save path for derivational rules, persist `_outputIntrinsicLevels` into the rule's `featureBindings` column. The `featureBindings` field on `MorphologicalRules` is a JSON map — for derivational rules it is currently empty/unused. Store the output intrinsic levels as: `{"outputIntrinsic": {"dimId": levelId, ...}}`. Use the existing `FeatureBindingsConverter` or store as raw JSON via a separate column if needed.

   Actually — check if `MorphologicalRule` already has an `outputIntrinsicLevelsJson` or similar column. If not, store it in the existing `featureBindings` JSON column under an `outputIntrinsic` key to avoid a schema migration. The `FeatureBindings` class stores `dims` (Map<int,int>) and `pos` (Set<int>). Extend the save logic to also write `outputIntrinsic` into the JSON map.

   Simplest approach: add a new `TextColumn get outputIntrinsicLevelsJson` to the MorphologicalRules table — BUT that requires schema migration. Instead, store it in the existing `featureBindings` JSON column using a convention: use negative dimension IDs (e.g., `-dimId`) to distinguish output intrinsic bindings from regular inflectional bindings. OR: store in a separate JSON key within featureBindings.

   Recommended approach to avoid schema changes: Store as a JSON string in the existing nullable `notes` or use the `featureBindings` JSON. Since `featureBindings` is typed via `FeatureBindingsConverter` as `{"dims": {...}, "pos": [...]}`, add an `"outputIntrinsic"` key: `{"dims": {...}, "pos": [...], "outputIntrinsic": {dimId: levelId}}`. Update `FeatureBindings` class to include an `outputIntrinsic` field (Map<int,int>) with backward-compatible JSON parsing (default to empty map if key missing).

**Wire to load:**
4. In `_loadFromExisting()`, when loading a derivational rule, read `_outputIntrinsicLevels` from `featureBindings.outputIntrinsic`.

**Clear on POS change:**
5. When `_outputPosId` changes, clear `_outputIntrinsicLevels = {}` so stale levels from a previous POS don't persist.
