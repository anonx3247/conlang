1. In `pos_dimensions_page.dart`, find the POS list tile rendering (where each POS is shown in the left pane). Add a delete `IconButton` to each POS tile:
   - Icon: `Icons.delete_outline`, size 18, color `colorScheme.error`
   - Shown on hover or always visible (match existing delete patterns — check if the POS list uses hover-reveal or always-visible delete buttons. If unclear, use always-visible with 0.5 opacity, full opacity on hover)

2. On delete tap, show a confirmation dialog. The dialog must:
   a. Query how many words (lexemes) use this POS: count lexemes where `partOfSpeech == pos.name` (lexemes store POS as a text field, not FK — verify by reading the Lexemes table schema)
   b. If word count > 0, show a migration picker:
      - Title: "Delete ${pos.name}?"
      - Body: "$wordCount word(s) use this POS. Reassign them to:"
      - A `DropdownButton<int>` listing all OTHER POS (exclude the one being deleted)
      - "Delete" button (red) — reassigns words then deletes POS
      - "Cancel" button
   c. If word count == 0, show a simpler dialog:
      - Title: "Delete ${pos.name}?"
      - Body: "This will also delete all its dimensions, inflectional rules, and markers for this POS. This cannot be undone."
      - "Delete" (red) + "Cancel"

3. On confirmed delete with migration:
   a. Update all lexemes with `partOfSpeech == deletedPos.name` to `partOfSpeech = targetPos.name` (since POS is stored as text in Lexemes, not as FK)
   b. Then call `morphologyDao.deletePos(pos.id)` — cascading FKs handle dimensions, markers, InflectionalRulePOS rows
   c. Also clean up MorphologicalRules where `inputPosId == pos.id` or `outputPosId == pos.id` — either delete them or null out the FK (check constraint behavior). Safest: null out the FK fields so derivational rules aren't silently deleted. Add:
      ```dart
      // Null out inputPosId/outputPosId on rules that reference the deleted POS
      await db.customStatement(
        'UPDATE morphological_rules SET input_pos_id = NULL WHERE input_pos_id = ?',
        [pos.id],
      );
      await db.customStatement(
        'UPDATE morphological_rules SET output_pos_id = NULL WHERE output_pos_id = ?',
        [pos.id],
      );
      ```
   d. Clear selection state if the deleted POS was selected

4. After deletion, if the deleted POS was the currently selected one, reset selection to the first remaining POS or null.

Note: The Lexemes table stores POS as a TEXT column `partOfSpeech` (free-text string like "Noun"), not an integer FK. Verify this by reading the Lexemes table definition in `app_database.dart`. The migration must update the text value, not an FK.
