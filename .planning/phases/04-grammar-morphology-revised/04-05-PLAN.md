7. **Implement `_recomputeTiebreak`** on the same state class:

```dart
void _recomputeTiebreak() {
  if (widget.kind != RuleKind.inflectional || _featureBindings.isEmpty) {
    _tiebreakConflict = null;
    return;
  }
  final selfBindings = FeatureBindings(
    pos: _selectedPosIdForChips == null ? const [] : [_selectedPosIdForChips!],
    dims: Map<int, int>.from(_featureBindings),
  );
  final allInflectionalAsync = ref.read(rulesByKindProvider(RuleKind.inflectional));
  final all = allInflectionalAsync.asData?.value ?? const <MorphologicalRule>[];
  final others = all
      .where((r) => r.id != widget.existing?.id)
      .map((r) => InflectionalRule.fromDbRow(r))
      .toList();
  final selfRule = InflectionalRule(
    id: widget.existing?.id ?? -1,
    name: widget.existing?.name ?? '(this rule)',
    source: '',
    isActive: true,
    bindings: selfBindings,
  );
  final conflicts = findDuplicateSpecificityConflicts([selfRule, ...others]);
  _tiebreakConflict = conflicts
      .where((c) => c.rules.any((r) => r.id == selfRule.id))
      .cast<TiebreakConflict?>()
      .firstWhere((_) => true, orElse: () => null);
}
```

**Executor note on `firstOrNull`:** If the Dart SDK version supports `.firstOrNull` on iterables (it does in 3.x via `package:collection` or stdlib), you can simplify the `conflicts.where(...).firstOrNull`. Otherwise, the `cast<T?>().firstWhere(_ => true, orElse: null)` fallback works.

```dart
testWidgets('live tiebreak banner appears when two rules have identical bindings and disappears when differentiated', (tester) async {
  await seedPosAndDimension(posName: 'Noun', posId: 1);

  // Seed two inflectional rules with identical bindings (PL on the Number dim)
  final rule1Id = await db.morphologyDao.insertRuleWithKind(
    MorphologicalRulesCompanion.insert(
      name: 'Plural A',
      source: 'suffix: s',
      featureBindings: Value(const FeatureBindings(pos: [1], dims: {1: 2})),
    ),
    RuleKind.inflectional,
  );
  await db.morphologyDao.insertRuleWithKind(
    MorphologicalRulesCompanion.insert(
      name: 'Plural B',
      source: 'suffix: es',
      featureBindings: Value(const FeatureBindings(pos: [1], dims: {1: 2})),
    ),
    RuleKind.inflectional,
  );

  // Fetch rule1 as the row passed to RuleEditorDialog as `existing`
  final rule1 = await (db.select(db.morphologicalRules)
        ..where((t) => t.id.equals(rule1Id)))
      .getSingle();

  await tester.pumpWidget(wrapDialog(
    RuleEditorDialog(kind: RuleKind.inflectional, existing: rule1),
  ));
  await tester.pumpAndSettle();

  // Assertion 1: banner present with the exact locked copy
  expect(find.textContaining('Conflict: This rule has the same specificity'), findsOneWidget);
  // Assertion 2: banner mentions the other rule by name
  expect(find.textContaining('Plural B'), findsOneWidget);

  // Toggle the PL chip OFF so rule1's bindings no longer match rule2
  await tester.tap(find.widgetWithText(FilterChip, 'PL'));
  await tester.pumpAndSettle();

  // Assertion 3: banner disappears
  expect(find.textContaining('Conflict: This rule has the same specificity'), findsNothing);
});
```

A broken tiebreak banner means users silently create conflicting inflectional rules and discover the problem only when their paradigm tables show `ParadigmAmbiguous` cells. The cost of an in-memory Drift widget test is one `setUp`/`tearDown` block (already in place); there is no technical blocker.
