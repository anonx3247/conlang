**Step 1: ParadigmUnmarked already carries the marker source.**

Check `paradigm_cell.dart`: `ParadigmUnmarked` already has `final MarkerDecl source;` which carries the marker that matched. This was added in plan 04-10. No change needed to the data model — the `source.id` gives us the `markerId` for the dialog.

If the `source` field were optional (for "uncovered" cells that became unmarked by default), we'd need to distinguish. **Step 2: Paradigm engine — verify marker source is surfaced.**

In `paradigm_engine.dart`, verify that when a marker matches, the engine creates `ParadigmUnmarked(root: ..., source: matchingMarker)`. This should already be the case from 04-10. If not, add the marker reference.

**Step 3: Cell click handler in paradigm_table_widget.dart.**

Find the cell click handler (likely in `_buildTable` or `_ParadigmCellWidget.build`). The click handler currently switches on `ParadigmCell` subtype:
- `ParadigmFilled` + `clickMode == ruleEditor` → opens RuleEditorDialog to edit the matching rule
- `ParadigmUncovered` + `clickMode == ruleEditor` → opens RuleEditorDialog in create mode with preFilledBindings
- `ParadigmUnmarked` → likely no handler yet or falls through

Add handling for `ParadigmUnmarked`:
```dart
case ParadigmUnmarked(source: final marker):
```
