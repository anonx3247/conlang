**Issue 28/38 — Level chip edit + standard-form icons unclickable (hit-test):**

The root cause is that `InkWell` and `IconButton` are nested inside `InputChip.label`. The `InputChip` absorbs tap events before inner widgets receive them.

**Fix approach:** Replace `InputChip` with a custom Row-based chip that gives each interactive element its own hit-test area. Two options — pick whichever is cleanest:

**Option A (preferred):** Replace `InputChip` with a Container styled to look like a chip (rounded border, background color, padding). Inside, use a Row with:
  - InkWell for edit icon (same as current)
  - Text for label
  - IconButton for standard-form (same as current, only if intrinsic)
  - An `IconButton` with `Icons.close` size 14 for the delete action (replaces InputChip.onDeleted)

This guarantees each element has its own gesture detector with no parent absorbing taps.

**Option B:** Keep InputChip but move the interactive elements OUTSIDE the label. Use a Row wrapping: [edit-InkWell, InputChip(label: Text(...)), standard-form-IconButton]. This preserves Material chip styling but puts icons outside the chip's tap area.

Choose Option A for maximum reliability. Style the container to match Material InputChip appearance:
```dart
Container(
  decoration: BoxDecoration(
    borderRadius: BorderRadius.circular(8),
    border: Border.all(color: theme.colorScheme.outline.withValues(alpha: 0.3)),
  ),
  padding: const EdgeInsets.symmetric(horizontal: 8, vertical: 4),
  child: Row(mainAxisSize: MainAxisSize.min, children: [...]),
)
```

Preserve the existing `_onEditLevel`, `_onAddLevel` callbacks. Preserve the D-86 level-deletion dependency check logic (currently in the `onDeleted` callback).
