**New Gap 7:** The search provider computes derived IPA forms on-the-fly but only compares the raw IPA form against the query. When a user searches "cimoma" (a romanized form), the engine produces the IPA form which doesn't match. The fix: also romanize the computed derived form before comparison.

1. In `filteredLexemeListProvider` (around line 165-180), after computing the derived IPA form via `engine.applyRule(rule, root.ipa, inventory)`, also romanize it and check both forms:

Current code (lines 170-175):
```dart
if (result case MorphSuccess(:final form)) {
  if (form != root.ipa &&
      form.toLowerCase().contains(query)) {
    computedDerivedMatchRootIds.add(root.id);
    break;
  }
}
```

Replace with:
```dart
if (result case MorphSuccess(:final form)) {
  if (form != root.ipa) {
    final romForm = romanize(form);
    if (form.toLowerCase().contains(query) ||
        (romForm.isNotEmpty && romForm.toLowerCase().contains(query))) {
      computedDerivedMatchRootIds.add(root.id);
      break;
    }
  }
}
```

2. The `romanize` function is available from `romanizeProvider`. Add a watch at the top of the provider (around the existing `ref.watch` calls near line 126-129):
```dart
final romanize = ref.watch(romanizeProvider);
```

Check if `romanizeProvider` is already imported/watched in this file. Search for existing `romanize` usage — it IS used later at line 414 (`final romText = romanize(form);`). So `romanizeProvider` is likely already available. If the provider function is obtained later in the file, hoist the `ref.watch(romanizeProvider)` call to the top of `filteredLexemeListProvider` so it's available in the computed-derived-match block.

3. Verify the import for `romanizeProvider` exists: `import '../../phonology/data/romanization_providers.dart';` — it should already be present given line 414 usage.
