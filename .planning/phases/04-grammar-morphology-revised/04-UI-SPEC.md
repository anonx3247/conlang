## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap (e.g. sidebar icon + label 10px uses nearest token) |
| sm | 8px | Chip row internal gaps, between-chip spacing |
| md | 16px | Panel internal padding, list item horizontal padding |
| lg | 24px | Empty-state icon-to-text gap, section breaks |
| xl | 32px | Major panel spacing |
| 2xl | 48px | Reserved; not used in dense desktop layout |
| 3xl | 64px | Empty-state icon size context |

Established patterns from codebase (source):
- Sidebar tile: `height: 40`, padding `horizontal: 16` — from `lexicon_shell.dart`
- ListView: `padding: EdgeInsets.all(16)` — from `rules_page.dart`
- Sidebar width: `200px` — from `lexicon_shell.dart`; Grammar shell must match
- Top tab bar height: `48px` row, `40px` button — from `app_shell.dart`

Touch target minimum: **48px** for any interactive cell in the paradigm table (Material 3 recommended minimum; aligns with `2xl` token).

Exceptions — Phase 4 tokens only:
- Sidebar tile height remains 40px (matches lexicon_shell.dart exactly — do not change)
- Paradigm table cells: minimum 48px tall × 64px wide to fit two-line rom/IPA stack with 4px internal vertical gap
- Template picker modal cards: 8px internal padding on all sides
- Tiebreaker banner / migration banner padding: 12px (see Spacing Exceptions — Inherited Legacy below)

### Spacing Exceptions — Inherited Legacy

These values appear in existing Phase 2/3 widgets that Phase 4 reuses without modification. They are not Phase 4 tokens and must not be changed.

| Value | Location | Usage | Status |
|-------|----------|-------|--------|

These are legacy exceptions acknowledged here for codebase fidelity. Phase 4 new widgets use the standard token set only.

## Typography

All sizes and weights from `lib/app.dart` ThemeData textTheme (source of truth):

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body / default | 13px | w400 | 1.4 | Rule names, cell content, form labels, derivation tree |
| Body small | 12px | w400 | 1.4 | IPA line in stacked cell, secondary metadata |
| Label small | 11px | w400 | 1.2, letterSpacing: 1.2 | Section headers in uppercase (e.g. "GRAMMAR", "LEXICON") |
| Heading / titleMedium | 15px (M3 default) | w600 | 1.2 | Sub-tab page titles, dialog titles, empty-state heading |

Two weights only: w400 (regular) and w600 (semibold). Matches `app_shell.dart` and `lexicon_shell.dart` conventions.

Paradigm table cell stacking:
- Line 1 (romanization): 13px w400 — `bodyMedium`
- Line 2 (IPA): 12px w400, `onSurface.withValues(alpha: 0.6)` — `bodySmall` dimmed
- When Alt held: lines swap — IPA on line 1 at 13px, romanization on line 2 at 12px dimmed
- If romanization is disabled project-wide: only IPA shown at 13px

Note on 12px/13px adjacency: the 1px gap between body (13px) and body small (12px) is intentional. Stacked paradigm cells require two visually distinct but close sizes so the IPA line reads as subordinate without shrinking to 11px, which is reserved for dense coverage matrix label text (labelSmall). The 1px difference is sufficient at desktop viewing distances given the accompanying alpha dimming (0.6) on the IPA line.

Coverage matrix cell text: 11px w400 (labelSmall) — abbreviated level names (e.g. "SG", "PL", "NOM")

## Component Inventory

All new components this phase must ship or extend. Each references the canonical prior-phase file.

### GrammarShell (new)
- Mirrors `lexicon_shell.dart` exactly: 200px sidebar (`surfaceContainerLow`) + VerticalDivider (`outlineVariant`) + Expanded content area.
- Section header: "GRAMMAR" in labelSmall (`onSurface.withValues(alpha: 0.5)`, letterSpacing: 1.2), padding `fromLTRB(16, 16, 16, 8)`.
- 4 sidebar items: POS & Dimensions / Inflectional Rules / Paradigm Viewer / Typology.
- Sidebar tile: height 40, `primaryContainer` when selected, `onPrimaryContainer` label/icon when selected.

### POS & Dimensions sub-tab (D-32)
- Master-detail layout: left POS list panel (fixed width ~260px) + right dimension editor panel (Expanded).
- POS list: ListView of selectable tiles, selected = `primaryContainer` bg. Add (+) IconButton at top-right of panel. Delete button per tile (Icons.delete_outline, `colorScheme.error`, shown on hover only).
- Dimension editor panel: shows selected POS name as `titleMedium` heading, then dimension cards in a scrollable list.
- Each dimension card: Card with 8px padding, shows dimension name + level chips. Add/remove levels inline. Drag handle icon (Icons.drag_handle) for reorder.
- "Add dimension" button: TextButton with Icons.add, triggers the template picker modal.
- "View paradigm template" link: TextButton navigates to Paradigm Viewer with this POS pre-selected.
- Inherits the existing POS editor for name/abbreviation CRUD (relocated from pos_page.dart, not redesigned). Editing POS name opens an inline dialog identical to existing POS dialog.

### Dimension Template Picker modal (D-05)
- Full-screen Dialog (AlertDialog with wide constraints: max-width 560px).
- Search TextField at top (hint: "Search templates…").
- Results grouped by type heading (Gender / Number / Case / Tense / Person / Aspect / Mood / Voice / Definiteness) using labelSmall uppercase headers.
- Each template card: Card with 8px padding. Name in bodyMedium w600. Level abbreviations in bodySmall dimmed. Tooltip (plain text, not markdown — keeps implementation simple) on hover showing the short description string from D-04.
- "Custom (blank)" entry in each group rendered as a last card with name "Custom" and no levels preview — allows starting from scratch without a template. (Resolves Claude's Discretion: always show custom-blank option.)
- Clicking a template card inserts the dimension into the POS as an editable instance and closes the modal.
- Tooltip waitDuration: 500ms (matches TooltipThemeData in app.dart).
- Tooltip format: plain text (not Markdown). The description strings from D-04 are single plain sentences.

### Inflectional Rules sub-tab (D-33)
- Port of `rules_page.dart` with `kind='inflectional'` filter applied.
- POS filter dropdown at top (existing pattern). Add a second filter: feature-value dropdown ("Show rules for: [dimension] = [level]") — optional filter, defaults to "All".
- Rule list items: same Card pattern as rules_page.dart. Feature binding tags shown as small Chips below the rule name (e.g. chip "Gender: M", chip "Number: PL").
- Reorder arrows (up/down): shown at 20% Opacity (disabled-gray, not hidden) for inflectional rules, matching the Phase 2 decision in STATE.md ("Disabled arrow buttons shown at 20% Opacity rather than hidden — preserves layout stability"). Arrows are non-functional for inflectional rules (tiebreaker is explicit error, not ordering — D-12), but the visual space is preserved. Tooltip on hover: "Rule ordering does not affect inflectional rule priority. Specificity determines which rule applies."
- Empty state: Icons.account_tree_outlined at 64px, `onSurface.withValues(alpha: 0.3)`. Heading: "No inflectional rules yet." Body: "Add a rule and bind it to dimension levels."

### Paradigm Viewer sub-tab (D-34, D-25, D-26, D-27)
- Top bar: POS dropdown + word picker (searchable TextField, scoped to selected POS) in a Row. When no word selected: show synthetic-root mode label "Showing template (no word selected)" in bodySmall italic dimmed.
- Axis config controls: compact Row of three DropdownButton widgets labelled "Rows:", "Columns:", "Tabs:". Persisted to project_settings per D-26.
- Paradigm table: placed below axis config. Side panel (coverage matrix) to the right.
- Layout: Row [ paradigm table (Expanded) | VerticalDivider | coverage matrix panel (240px) ]. Coverage matrix is a permanent side panel, not a mode toggle. (Resolves Claude's Discretion: separate panel always visible.)
- Empty POS state: Icons.table_chart_outlined, "Select a POS to view its paradigm."

### Paradigm Table widget (shared — Grammar Paradigm Viewer + Lexicon word detail)
- 2-axis table for 2-dim POS: rows = dim A levels, columns = dim B levels.
- 3+ dim POS: 2 axes as table + TabBar or DropdownButton above the table for the remaining dims (each tab/option = one level of the third dimension). Use TabBar if ≤ 6 slices, DropdownButton if > 6.
- Each cell: Column[ ViolationText(romanization), Text(IPA, bodySmall dimmed) ]. Width min 64px, height min 48px. Internal vertical gap: 4px.
- Normal cell: background `colorScheme.surface`, border `colorScheme.outlineVariant` (0.5px).
- Override cell: background `Colors.amber.withValues(alpha: 0.15)`, border `Colors.amber.withValues(alpha: 0.4)`, text color `Colors.amber.withValues(alpha: 0.8)`. Icon: Icons.warning_amber_outlined at 12px in top-right corner of cell.
- Uncovered cell: shows em-dash "—" at bodyMedium `onSurface.withValues(alpha: 0.3)` + Icons.add_circle_outline at 14px in `onSurface.withValues(alpha: 0.2)`. Clicking an uncovered cell opens the override dialog pre-seeded with empty fields AND shows an inline option "Create rule for this cell" as a TextButton inside the dialog. (Resolves Claude's Discretion: both em-dash AND create-rule shortcut in dialog, not a floating button on the cell itself.)
- Hover on filled cell: show Tooltip listing the rule chain. Format: "`-ar` (Gender+Number) → `-e` (Case)". waitDuration 500ms.
- Column/row headers: level name (e.g. "SG", "PL") in labelSmall w600. Background `colorScheme.surfaceContainerLow`.
- ViolationText widget used on each cell's romanization line (per D-30 and Phase 3 plan 03-05).
- Alt-held: cells flip to IPA-first display app-wide (Phase 3.1 FIX-05 contract unchanged).
- Clicking any cell opens the Cell Override Dialog (see below).

### Coverage Matrix panel (D-15, D-34)
- 240px fixed-width panel to the right of the paradigm table in the Grammar Paradigm Viewer sub-tab.
- Title: "Coverage" in labelSmall uppercase.
- Grid showing one row per dimension level, one column per other dimension level (or simpler: flat list of {dim, level} pairs).
- For each {dim, level} pair: a row showing level name + a colored dot/chip: green (has at least one matching rule), red (no matching rule exists).
- Green indicator: `Colors.green.shade600` dot, 8px diameter.
- Red indicator: `colorScheme.error` dot, 8px diameter.
- Uses `paradigmCoverageMatrixProvider(posId)` Riverpod provider.
- In Lexicon word detail panel: coverage matrix is NOT shown (per D-27, Lexicon is read-only reflection of Grammar axis config; keep the panel compact).

### Tiebreaker Error (D-12)
- Inline warning banner inside the **Rule Editor dialog** (not a toast). (Resolves Claude's Discretion: inline banner only, no toast. Toast is too ephemeral for a data-integrity issue the user must resolve.)
- Banner: `Container` with `colorScheme.errorContainer` background, `colorScheme.onErrorContainer` text, border `colorScheme.error` (1px), rounded 4px, padding 12px.
- Icon: Icons.warning_outlined, 16px, `colorScheme.error`.
- Text: "Conflict: This rule has the same specificity as '[other rule name]' and both match overlapping cells. Add a distinguishing dimension binding to resolve." bodySmall.
- Banner appears below the "Applies to" chip rows when a conflict is detected (live check on every chip toggle).
- Also shown inline in the **Paradigm Viewer** cell tooltip when a cell is ambiguous: tooltip text appended with " | [CONFLICT] Two rules matched with equal specificity".

### Cell Override Dialog (D-28)
- AlertDialog, title: "Edit cell: [dim1=level] [dim2=level] …" assembled from the cell's feature set.
- Fields: romanization TextField (primary, IpaTextField for IPA keyboard access), IPA TextField (auto-derived from romanization on first input via reverse-romanization, then editable).
- Uncovered cell: add a TextButton "Create a rule for this cell" that navigates to Inflectional Rules sub-tab with the feature pre-filled. This closes the dialog and deep-links to the rule editor.
- Covered cell: "Clear override" TextButton (shown only when an override exists), which removes the exception row and reverts to computed form.
- Save / Cancel actions in dialog actions bar.

### Rule Editor Dialog (D-40, D-42) — extended
- Constructor: `RuleEditorDialog({MorphologicalRule? existingRule, required RuleKind kind})`.
- Inflectional mode: "Applies to" section at top. One Row per dimension of the currently-selected POS. Each row: dimension name label + Wrap of FilterChip widgets (one per level). Selected chips = filled; unselected = outlined. Chip label: level abbreviation (e.g. "SG", "PL", "NOM"). No chips selected across all dimensions = validation error: "Inflectional rules must bind at least one feature." shown in red bodySmall below the chip rows.
- Derivational mode: "Input POS" DropdownButton + "→" label + "Output POS" DropdownButton at top. Output POS defaults to input POS.
- Shared (both modes): DSL field (IpaTextField), structured ops editor (existing _OpState pattern), branching/conditions editor, live preview panel (preview_panel.dart), name TextField, active Toggle switch.
- Tiebreaker warning banner (see above): rendered between "Applies to" chips and the DSL field when conflict detected.

### Lexicon > Derivations sub-tab (D-36, D-37, D-38)
- 4th item in LexiconShell sidebar: label "Derivations", icon Icons.transform, path `/lexicon/derivations`.
- Content: port of `rules_page.dart` with `kind='derivational'` filter.
- Rule list item extended: shows rule name (bodyLarge w600) + DSL preview (bodySmall `onSurface.withValues(alpha: 0.5)`) + "Input POS → Output POS" row using small chips (bodySmall, `surfaceContainerLow` bg).
- Empty state: Icons.transform_outlined at 64px. Heading: "No derivational rules yet." Body: "Existing morphological rules have been moved here."

### Typology sub-tab (D-35)
- Simple form layout: padding 24px all sides.
- Page title: "Typology" in headlineSmall (titleMedium w600).
- Three labeled sections, each: label (bodyMedium w600) + info tooltip icon (Icons.info_outline, 14px, `onSurface.withValues(alpha: 0.5)`) + DropdownButtonFormField.
- Fields: Alignment (options: NOM-ACC, ERG-ABS, Split-ERG), Basic Word Order (SVO, SOV, VSO, VOS, OVS, OSV, Free / Topic-prominent), Modality Strategy (Synthetic, Analytic, Mixed).
- Tooltip text is plain text (matching D-04 pattern). waitDuration 500ms.
- Spacing between sections: 24px.
- Save: auto-saves to project_settings on each field change (no explicit save button — UX matches the existing Phase 1 project_settings pattern).

### One-time migration banner (D-24 consequence)
- Rendered at the top of the Inflectional Rules sub-tab AND Lexicon > Derivations sub-tab on first open after v7→v8 migration. (Resolves Claude's Discretion: show the banner in both destination locations where content moved to.)
- Dismissible Container: `colorScheme.surfaceContainerHigh` background, `colorScheme.primary` left-border (3px), padding 12px.
- Icon: Icons.info_outline, `colorScheme.primary`, 16px.
- Text: "Morphology rules have been moved here. Existing rules are now Derivational rules in Lexicon → Derivations. Create Inflectional rules here to drive paradigm tables."
- Dismiss: IconButton Icons.close at right edge. Dismissal stored in project_settings key `"ui.migration_v8_banner_dismissed"`.
- Only shown once per project per sub-tab.

## Interaction Contracts

### Paradigm cell — click behavior
1. Click any cell → open Cell Override Dialog.
2. If cell is uncovered: dialog offers "Create a rule for this cell" TextButton that closes dialog and navigates to Inflectional Rules sub-tab with the cell's feature set pre-populated in the chip picker.
3. If cell has override: dialog pre-fills with override values; "Clear Override" TextButton appears in dialog.
4. If cell is filled (no override): dialog pre-fills with computed form (read-only top section) + override input fields below.

### Paradigm cell — Alt-held
- Cells swap rom↔IPA display (line 1 ↔ line 2). Inherits app-wide Alt-held contract from Phase 3.1 FIX-05. No new implementation needed.

### Feature binding chips — inflectional rule editor
- Each chip is a FilterChip: selected state = `colorScheme.primaryContainer` fill, unselected = outlined.
- Chip rows update dynamically when the POS selection changes (chips re-render for new POS's dimensions).
- Conflict detection runs on every chip toggle; banner appears/disappears live.

### Dimension reorder (POS editor)
- Drag handle (Icons.drag_handle) visible on each dimension card in POS editor.
- ReorderableListView with horizontal drag handles.

### Template picker — search
- Search TextField filters the grouped list in real-time. Empty search shows all groups.
- Groups with no matches are hidden.

### Typology — auto-save
- Each DropdownButtonFormField onChanged triggers immediate project_settings write.
- No save button. Visual feedback: none required (save is instant and non-destructive).

### Coverage matrix — updates
- Coverage matrix reacts via Riverpod stream: any inflectional rule insert/update/delete triggers recomputation via `paradigmCoverageMatrixProvider(posId)`.
