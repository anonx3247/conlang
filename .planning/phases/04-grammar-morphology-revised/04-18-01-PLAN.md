**Issue 13 — Promoted derivation edit pane shows root IPA:**

In `word_detail_panel.dart:_startEditing()` (line ~126-153), the method reads raw `lexeme.ipa` and `lexeme.romanization` to seed the text controllers. For promoted derivations, these fields contain the parent root's values (placeholder stubs). Fix:

1. At the start of `_startEditing`, resolve the display forms using the same pattern as `_buildViewMode`:
   ```dart
   final promoted = ref.read(promotedDerivedFormProvider(lexeme.id));
   final display = resolveDisplayForms(lexeme, promoted);
   ```
2. Replace `_ipaController.text = lexeme.ipa;` with `_ipaController.text = display.ipa;`
3. Replace `_romanizationController.text = lexeme.romanization ?? '';` with `_romanizationController.text = display.rom;`
4. Update the `_ipaManuallyEdited` check to use `display.ipa` and `display.rom` instead of `lexeme.ipa` and `lexeme.romanization`.

**Issue 35b — [bracket] display shows phonemic not phonetic:**

The `[bracket]` display in both `word_list_panel.dart` and `word_detail_panel.dart` currently renders `display.ipa` which is the phonemic (pre-rewrite) form. It should show the post-rewrite (phonetic) form.

In `word_list_panel.dart`, find the two bracket display locations (around lines 505-525 and 700-718) where `display.ipa` is rendered inside `[...]` brackets. For each:
1. Add `final applyRewrite = ref.watch(applyRewritePipelineProvider);` (import from phonotactic_providers.dart if not already imported)
2. Compute `final phonetic = applyRewrite(display.ipa);`
3. Replace the `text: display.ipa` inside the bracket ViolationText with `text: phonetic`
4. NOTE: The ViolationText violations still reference `display.ipa` offsets — the violations should still be computed against `display.ipa` (phonemic), but the DISPLAYED text in brackets should be `phonetic`. Since ViolationText highlights based on character offsets and the phonetic form may have different character positions, switch the bracket content from ViolationText to a plain Text widget showing `phonetic`, and keep ViolationText only for the non-bracketed IPA display.

In `word_detail_panel.dart` `_buildViewMode`, apply the same fix. The bracket display is NOT currently present in word_detail_panel view mode (it shows IPA directly), but the IPA sub-label at ~line 486 shows `display.ipa`. Check if brackets are rendered — if so, apply the phonetic fix. If not, leave as-is (the IPA label correctly shows phonemic form which gets romanized).

IMPORTANT: The bracket `[...]` notation in linguistics means PHONETIC (post-rewrite). The slash `/.../` notation means PHONEMIC (pre-rewrite). So `[bracket]` content MUST use the post-rewrite form.

**Issue 39a — POS pill doesn't show intrinsic level:**

In `word_detail_panel.dart:_buildViewMode()` around line 636-651, the POS Chip currently shows just `lexeme.partOfSpeech!`. Fix:

1. After the POS check, decode the intrinsic levels:
   ```dart
   final intrinsicLevels = IntrinsicLevelsCodec.decode(lexeme.intrinsicLevelsJson);
   ```
2. Look up dimension and level names. Watch `dimensionsForPosProvider` for the POS. For each intrinsic dimension, find the matching level name from the dimension's levels list.
3. Build a label suffix like `(Masculine)` or `(Masculine, Singular)` from the resolved level names.
4. Update the Chip label from `lexeme.partOfSpeech!` to `'${lexeme.partOfSpeech!} ($levelNames)'` when intrinsic levels are assigned, or just `lexeme.partOfSpeech!` when none are.

Need to resolve the POS id from the POS name. Use `posForLexeme(lexeme, posList)` (already available in `_buildViewMode` — if not, add the watch). Then watch `dimensionsForPosProvider(pos.id)` to get dimensions with levels.

**Enhancement — Clickable parent pills in word detail:**

In `WordDetailParentsSection._buildParentRow()` (line ~1203-1224), the parent info is currently rendered as a plain `Text`. Make it navigable:

1. Wrap the Text in a `GestureDetector` or `InkWell` with `onTap`.
2. On tap, update the selected lexeme to the parent's id. The word detail panel is driven by the selected-word state. Use the same navigation pattern as the dictionary list — look for `selectedLexemeIdProvider` or equivalent state notifier.
3. Check how word selection works: if there's a `ref.read(selectedLexemeIdProvider.notifier).state = parentId` pattern, use it. Otherwise check for GoRouter query param navigation.
4. Style the parent label as a Chip or as underlined text to indicate clickability. A small Chip with the parent's label and an arrow icon is most consistent with the existing POS chip style.

The parent section is a ConsumerWidget so it has `ref` access. Use `ref.read` for the navigation action.
