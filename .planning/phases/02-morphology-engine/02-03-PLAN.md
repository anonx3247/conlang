**2. `rule_editor_dialog.dart` -- Hybrid rule editor (ConsumerStatefulWidget):**

This is the core authoring experience. It opens as a large dialog (or full-page on smaller screens).

**Top section: Rule name** -- TextField for the rule name.

**Middle section: Branches** -- Vertical list of branch cards. Each branch card contains:

a) **Condition row** at the top:
   - Dropdown: "Default (always)" / "Ends with literal" / "Starts with literal" / "Ends with class" / "Starts with class"
   - When not "Default": a TextField for the literal string or class name (with hint text like `"o"` or `stop`)
   - The first branch defaults to "Default" for simple rules; user can change it

b) **Operations list** within the branch:
   - Each operation is a row with:
     - **Type dropdown**: Prefix / Suffix / Infix / Ablaut / Template / Reduplication / Suppletive
     - **Type-specific fields** (per research Pattern 8):
       | Type | Fields |
       |------|--------|
       | Prefix | `affix` TextField (IPA, use IpaTextField if available) |
       | Suffix | `affix` TextField |
       | Infix | `affix` TextField + `after consonant #` number field |
       | Ablaut | `from` TextField + `to` TextField |
       | Template | `pattern` TextField + help text "digits = consonant slots, vowels are literal" |
       | Reduplication | `scope` dropdown (Full/CV/C) + `position` dropdown (Prefix/Suffix) |
       | Suppletive | `form` TextField (the literal override form) |
     - Remove operation button (X icon)
   - "Add operation" button at bottom of each branch's operation list

c) **Remove branch** button (only if more than one branch)

- "Add branch" button at the bottom of the branches list to append a new branch card

**Live DSL expression display** -- Below the form, a `Container` with monospace text showing the DSL expression computed from the current form state. Call `serializeMorphRule()` on the in-memory `MorphologicalRule` built from the form state. Update on every form change.

**Action buttons** -- Cancel / Save. Save validates (name not empty, at least one branch with at least one operation), then inserts or updates via DAO.

**State management:** Use local `StatefulWidget` state for the form (list of branch models, each with condition + operations). Build a `MorphologicalRule` from form state for DSL serialization and preview. Do NOT use Riverpod for in-editor ephemeral state.

**3. `preview_panel.dart` -- Preview table (ConsumerStatefulWidget):**

Embedded within the rule editor dialog (below the DSL display or in a side panel if width allows).

- **Sample word generation**: Read phoneme inventory and phonotactic templates from providers (same data as WordGenerator). Generate 5-8 sample words using `WordGenerator.generateWords()`.
- **Preview table**: Two-column layout. Left column: root word (monospace). Right column: derived form (monospace) or error message (red/italic). Arrow icon between columns.
- **Debounce**: Use a `Timer` (300ms) that re-evaluates the preview whenever form state changes. Cancel previous timer on each change.
- **Evaluation**: Build a `MorphologicalRule` from form state, create a `MorphologyEngine`, call `applyRule()` on each sample word. Display `MorphSuccess.form` or `MorphNoMatch.reason`.
- **Error display**: If the DSL serialization or rule construction fails, show the error inline where the preview table would be.
- **Empty inventory**: If no phonemes/templates defined, show "Define phonemes and phonotactic templates first to see a preview" message.

IMPORTANT per locked decisions:
- Hybrid authoring: structured form fields WITH live DSL expression shown alongside (users learn the syntax)
- Dropdown for operation type selection (Prefix, Suffix, Infix, Ablaut, Template, Reduplication, Suppletive)
- Live debounced updates (~300ms)
- Inline error messages when a sample word has no matching branch
- Auto-generated sample words from phonotactic rules as preview input
