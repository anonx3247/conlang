**Domain model changes (morphology_dsl.dart):**

1. Replace the 4 existing condition sealed subclasses with a unified `PatternCond`:
```dart
sealed class MorphCondition {
  const MorphCondition();
}

/// Pattern-based condition using phonological notation.
///
/// Pattern elements:
/// - `[className]` — matches any phoneme in the named natural class
/// - Single uppercase letter: `C` = any consonant, `V` = any vowel
/// - Lowercase letters: literal phoneme match (e.g. `k`, `na`)
/// - `(group)` — optional group (matches zero or one occurrence)
/// - `_` at start = pattern must match word start (anchored prefix)
/// - `_` at end = pattern must match word end (anchored suffix)
/// - No anchors = pattern matches anywhere in the word
///
/// Examples:
/// - `[nasal]V_` — ends with nasal + vowel
/// - `_CV` — starts with consonant + vowel
/// - `Vk(l)_` — ends with vowel + k + optional l
/// - `[stop][stop]` — contains two consecutive stops anywhere
class PatternCond extends MorphCondition {
  const PatternCond(this.pattern);
  final String pattern; // Raw pattern string
}
```

2. Keep the old classes temporarily as deprecated aliases for backward compat, OR remove them entirely and update all references. Since the codebase is small, remove them entirely:
   - Delete `EndsWithLiteralCond`, `StartsWithLiteralCond`, `EndsWithClassCond`, `StartsWithClassCond`

3. Update the DSL condition parser `_buildConditionParser()`:
   - The new condition syntax in DSL source uses `{pattern}` (curly braces) to wrap the pattern string in a branch. This avoids ambiguity with operation syntax.
   - Parser: `char('{') & pattern('^}').plus().flatten() & char('}')` maps to `PatternCond(patternStr)`
   - Keep `char('_')` as the default/else branch (null condition)
   - For backward compatibility with existing rules stored in DB that use old `"lit"_` or `[class_]` syntax: add a migration parser that converts old-style conditions to PatternCond on load. Specifically:
     - `"lit"_` (old EndsWithLiteral) → `PatternCond('lit_')` (literal + end anchor)
     - `_"lit"` (old StartsWithLiteral) → `PatternCond('_lit')` (start anchor + literal)
     - `[class_]` (old EndsWithClass) → `PatternCond('[class]_')` (class + end anchor)
     - `[_class]` (old StartsWithClass) → `PatternCond('_[class]')` (start anchor + class)
   - The parser should try: new `{pattern}` syntax FIRST, then old syntax forms (for DB migration), then `_` for default.

4. Update the DSL condition serializer `_serializeCondition()`:
```dart
String _serializeCondition(MorphCondition cond) {
  return switch (cond) {
    PatternCond(:final pattern) => '{$pattern}',
  };
}
```

**Engine changes (morphology_engine.dart):**

5. Update `matchesCondition` (or wherever conditions are evaluated) to handle `PatternCond`:
   - Parse the pattern string into segments: `[className]`, `C`, `V`, literal chars, `(optional)`, `_` anchors
   - Use a simple left-to-right matcher against the IPA-tokenized word:
     - If pattern starts with `_`: anchor to word start
     - If pattern ends with `_`: anchor to word end
     - `[className]`: resolve via `inventory.naturalClasses[className]` and check if the current token is in the class
     - `C`: check if current token is in `inventory.consonants`
     - `V`: check if current token is in `inventory.vowels`
     - Lowercase literal: exact match against current token
     - `(group)`: try matching the group; if it fails, skip (zero occurrences)
   - Return true if the pattern fully matches (all segments consumed, anchoring satisfied)
   - For non-anchored patterns, try matching at every position in the word

6. Remove old condition matching code for the 4 deleted condition types. Also remove the auto-strip behavior that was tied to `EndsWithLiteralCond` — the new pattern system is purely a match check; stripping is done by explicit `RemoveSuffixOp` in the operation chain.
