**morphology_dsl.dart -- Full implementation:**

1. **Data model** (sealed classes as designed in research, already stubbed in Task 1):
   - `MorphOperation` sealed class with: `PrefixOp(affix)`, `SuffixOp(affix)`, `InfixOp(affix, position)`, `AblautOp(from, to)`, `TemplateOp(pattern)`, `RedupOp(scope, position)`, `SuppleteOp(form)`
   - `MorphCondition` sealed class with: `EndsWithLiteralCond(suffix)`, `StartsWithLiteralCond(prefix)`, `EndsWithClassCond(classRef)`, `StartsWithClassCond(classRef)`
   - `MorphBranch(condition, operations)`
   - `MorphologicalRule(id, name, branches, source)`
   - `ParsedMorphRule` with `.success(rule)` / `.failure(error, source)` named constructors

2. **DSL Parser** using petitparser 7.x combinators. The grammar (per CONTEXT.md locked decisions):
   - Branches separated by `|` (pipe)
   - Each branch: optional condition spec + operation sequence
   - Condition specs: `[C_]` (ends with class C), `[_C]` (starts with class C), `"lit"` with `_` suffix/prefix for ends/starts-with, `_` alone = default
   - Operations: `+affix` = suffix, `affix+` = prefix, `-"str"` = remove trailing, `/from/to/` = ablaut, bare pattern with digits = template, `redup:scope:position` = reduplication, `="form"` = suppletive
   - Use petitparser `case Success() / case Failure()` pattern matching (not isFailure)
   - `flatten()` with no argument or named `message:` param only

3. **DSL Serializer** `serializeMorphRule(MorphologicalRule rule) -> String`: Reconstructs the source string from the data model. Must round-trip correctly with the parser.

**morphology_engine.dart -- Full implementation:**

1. **IPA tokenizer**: Extract the tokenization logic from `WordGenerator._tokenize` into a public top-level function `tokenizeIpa(String word, PhonemeInventory inventory) -> List<String>` that returns just the symbol strings (not the offset tuples). Import `PhonemeInventory` from `word_generator.dart`.

2. **Class resolver**: Extract `_resolveClass` logic into a public function `resolvePhonemeClass(String classRef, PhonemeInventory inventory) -> List<String>`.

3. **Condition matcher**: `bool conditionMatches(MorphCondition? cond, String root, PhonemeInventory inventory)` using switch expression over sealed MorphCondition. Guard for empty roots.

4. **Operation appliers**: Each as a pure function:
   - `applySuffix(root, affix) -> root + affix`
   - `applyPrefix(root, affix) -> affix + root`
   - `applyInfix(root, affix, position, inventory)`: tokenize, find Nth consonant, insert after it
   - `applyAblaut(root, from, to, inventory)`: tokenize, replace matching tokens, rejoin
   - `applyTemplate(root, pattern, inventory)`: extract consonants, substitute numbered slots
   - `applyRedup(root, scope, position, inventory)`: extract scope portion, prepend/append
   - `applySuppletive(form) -> form` (ignores root entirely)

5. **Engine entry point**: `MorphologyEngine` class with `applyRule(rule, root, inventory) -> MorphResult`. Iterates branches, checks conditions, applies operations in sequence. Returns `MorphNoMatch` if no branch matches.

IMPORTANT: The tokenizer and class resolver must be extracted as PUBLIC standalone functions (not private methods on WordGenerator) so the morphology engine can import them. Create them in `morphology_engine.dart` or in a shared utility. Do NOT modify `word_generator.dart` -- duplicate the logic (it is <30 lines) to avoid coupling. The existing `_tokenize` returns `(String, int)` tuples; the morphology version returns just `List<String>`.
