<objective>
Fix SearchableParentSelector to display computed derived forms instead of raw
placeholder values for promoted-derivation lexemes.

Purpose: UAT Test 1 reported that the autocomplete dropdown "shows the
non-derived forms instead of the full forms of words." Promoted-derivation
Lexeme rows store `ipa = parent.ipa` and `romanization = null` as placeholders
(per design D-58). The widget reads these raw fields directly, so it displays
the parent's phonemes instead of the computed derived form. The
`promotedDerivedFormProvider` and `resolveDisplayForms()` helper already exist
and are correctly used by `EtymologyChainSection` — they just need to be wired
into `SearchableParentSelector`.

Output: Updated `searchable_parent_selector.dart` that shows correct derived
forms everywhere.
</objective>

```dart
class PromotedDerivedForm {
  const PromotedDerivedForm({required this.ipa, required this.romanization});

/// Returns (rom: String, ipa: String) — uses promoted computation when
/// the row is a rule-linked derivation, otherwise falls back to stored fields.
({String rom, String ipa}) resolveDisplayForms(
  Lexeme lexeme,
  PromotedDerivedForm? promoted,
);

/// Provider.family<PromotedDerivedForm?, int> — keyed by lexeme ID.
/// Returns null for non-promoted lexemes.
final ProviderFamily<PromotedDerivedForm?, int> promotedDerivedFormProvider;
```

Modify `SearchableParentSelector` in three locations to use `resolveDisplayForms`
with `promotedDerivedFormProvider` instead of reading raw `lx.romanization` and
`lx.ipa` fields directly.

**Helper method — add a private method to `_SearchableParentSelectorState`:**

```dart
/// Resolves the display label for a lexeme, using the promoted derived form
/// when the lexeme is a promoted derivation row (D-58 placeholder resolution).
String _labelForLexeme(Lexeme lx) {
  final promoted = ref.read(promotedDerivedFormProvider(lx.id));
  final forms = resolveDisplayForms(lx, promoted);
  return lx.meaning != null ? '${forms.rom} \u2014 ${lx.meaning}' : forms.rom;
}
```

Use `ref.read` (not `ref.watch`) because this method is called from
`Autocomplete` callbacks (`optionsBuilder`, `_displayStringForOption`) which
execute during the build phase but are not directly in the widget tree — they
are closures passed to `Autocomplete`. `ref.read` is correct here for
point-in-time reads. The widget will rebuild when the underlying providers
change because `allLexemeListProvider` is already watched in `build`.

**Location 1 — `_displayStringForOption` (line ~56-61):**

Replace the body with a call to `_labelForLexeme(lx)`:

```dart
String _displayStringForOption(Lexeme lx) => _labelForLexeme(lx);
```

**Location 2 — `optionsBuilder` search predicate (lines ~86-93):**

The `.where` clause that filters by `lx.ipa`, `lx.romanization`, and
`lx.meaning` must also match against the resolved derived forms. Replace the
second `.where` with:

```dart
.where((lx) {
  // Match against resolved display forms (handles promoted derivations)
  final promoted = ref.read(promotedDerivedFormProvider(lx.id));
  final forms = resolveDisplayForms(lx, promoted);
  return forms.rom.toLowerCase().contains(query) ||
      forms.ipa.toLowerCase().contains(query) ||
      (lx.meaning?.toLowerCase().contains(query) ?? false);
})
```

This ensures that typing a substring of a derived word's computed
romanization or IPA will find it, not just the raw placeholder values.

**Location 3 — Selected pills in the `Wrap` section (lines ~123-131):**

Replace the inline label computation in the `Builder` with `_labelForLexeme`.
The `Builder` wrapping can remain for null-safety on the lexeme lookup:

