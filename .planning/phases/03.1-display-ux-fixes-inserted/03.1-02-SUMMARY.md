# Phase 3.1 Plan 02: Word Display and Anki Format Fix Summary

**One-liner:** Corrected linguistic notation in word generator (romanization plain + [IPA]) and Anki export (romanization line 1 + HTML br + [IPA] line 2), removing slash notation throughout.

## What Was Built

### Task 1: Word Generator Display

Modified `_WordRow.build()` in `word_generator_panel.dart` to swap display order:

**Before:** IPA as primary text + `/ romanized /` secondary (slash notation)

**After:**
- When romanization exists: `romanized` (bodyMedium, plain) + 8px gap + `[IPA]` (bodySmall, alpha 0.55, with violation underline)
- When no romanization: plain IPA only (bodyMedium, unchanged)

The `ViolationText` widget's `style` parameter is used to pass bodySmall styling to the secondary IPA display. Square brackets are embedded in the text string as `'[$word]'`.

### Task 2: Anki Card Front Field

Modified `_insertNotes()` in `anki_exporter.dart`:

**Before:** `'${_htmlEscape(e.ipa)} [${_htmlEscape(e.romanization!)}]'` (IPA first, romanization bracketed)

**After:** `'${_htmlEscape(e.romanization!)}<br>[${_htmlEscape(e.ipa)}]'` (romanization line 1, [IPA] line 2)

HTML escaping is preserved for both fields — `_htmlEscape` applied to romanization and IPA before HTML insertion. This maintains the existing T-3.1-04 mitigation.
