<objective>
Overhaul the project data layer to support .conlang file format with user-chosen storage locations, rename, save-as, and recent projects tracking.

Purpose: Currently projects are stored as `{appDocs}/conlang/{id}/project.db` with no user control over location. This plan refactors the data layer so projects are standalone .conlang files (SQLite DB with custom extension) that the user places anywhere, with a recent-projects index for quick access. This is the foundation for Plan 03's UI changes.
Output: Updated Project model, refactored ProjectRegistry, new RecentProjectsService, updated providers.
</objective>

    Per D-07 — `createProject(String name, String filePath)`:

    - Register in registry.json with the filePath
    - Return new Project

    Per D-08 — `openProjectFile(String filePath)`:
    - New method: registers an existing .conlang file in the registry
    - Reads the file to verify it exists
    - Creates a Project entry with name derived from filename (strip .conlang extension)
    - If already registered (same filePath), just return existing entry
    - Returns Project

    Per D-09 — `duplicateProject(String sourceId, String newFilePath)`:
    - New method: copies the .conlang file from source project's filePath to newFilePath
    - Registers the copy as a new project in the registry
    - Returns new Project

    Per D-10 — `renameProject(String id, String newName)`:
    - New method: updates the display name in registry.json
    - Does NOT rename the file on disk (per D-10: "stored in project metadata, not filename")

    **Important migration note:** Existing projects stored at `{baseDir}/{id}/project.db` must still work. In `listProjects()`, for any project that has the old `directoryPath` format without a `.conlang` extension in filePath, treat them as legacy.
