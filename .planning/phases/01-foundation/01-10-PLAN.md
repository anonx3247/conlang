  <name>Task 1: Diagnose and fix IPA keyboard popup dismissal</name>
  <files>lib/features/phonology/presentation/shared/ipa_keyboard/ipa_text_field.dart</files>
  <action>
The previous fix (plan 08, commit 234167a) added TapRegion groupId sharing and disabled TextField's onTapOutside, but UAT retest shows the popup still closes on symbol click. The user reports "clicking anywhere in it just closes it."

Investigate these likely causes:
1. The OverlayPortal overlay child may be positioned OUTSIDE the TapRegion group boundary in the widget tree — CompositedTransformFollower renders in overlay space, and TapRegion hit testing may not reach it. If this is the case, the TapRegion on the overlay side is never consulted.
2. The `_onFocusChanged` listener fires a microtask to hide popup on blur, but symbol button taps in the overlay may cause a brief focus loss that the microtask does not recover from (race condition with `_focusNode.requestFocus()` in `_insertSymbol`).
3. The `_SymbolButton` uses `InkWell.onTap` which may trigger a pointer-down that causes the text field to lose focus before the TapRegion logic runs.

Fix approach — try these in order until UAT passes:
- Ensure the overlay TapRegion is functioning: add a debug print inside the overlay's TapRegion onTapOutside to verify it is being called (remove before commit). If it never fires, the overlay is outside the group.
- If the issue is focus loss during symbol tap: change `_onFocusChanged` to use a longer delay (e.g., `Future.delayed(Duration(milliseconds: 100))`) instead of `Future.microtask()` so that `_insertSymbol`'s `_focusNode.requestFocus()` has time to reclaim focus before the hide check runs.
- If the issue is that OverlayPortal content is outside TapRegion hit test: wrap the entire OverlayPortal (including its overlay child builder output) inside a single TapRegion using a different approach — use `FocusScope` or a `_popupInteracting` boolean flag set on pointer-down inside the popup and cleared on pointer-up, checked in `_onFocusChanged` before hiding.
- As a robust fallback: in `_onFocusChanged`, before calling `_hidePopup()`, check `_popupVisible && !_focusNode.hasFocus` but add a `_isInteractingWithPopup` flag that `IpaKeyboardPopup` sets via a callback on pointer-down events. The popup calls `onInteractionStart` on `PointerDownEvent` and `onInteractionEnd` on `PointerUpEvent`. If `_isInteractingWithPopup` is true, skip the hide.

The fix must pass this test: focus an IpaTextField, popup appears, click 5 different symbols in sequence — all 5 insert correctly and popup remains open. Click outside — popup dismisses.
  </action>

Run `flutter analyze` — no new warnings. Manually test in the app: focus IPA text field, click multiple symbols in popup, verify popup stays open and symbols are inserted. Click outside to dismiss.
  </verify>
