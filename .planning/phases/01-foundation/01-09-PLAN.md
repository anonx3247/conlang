Redesign the PhonemeEditDialog to fix three issues from UAT:

**1. Remove redundant IPA symbol text field, auto-derive symbol from features:**

The current dialog shows both an IPA text field AND feature dropdowns (manner/place/voicing for consonants, height/backness/rounding for vowels). Since selecting features already determines the IPA symbol, the manual IPA input is redundant.

Approach: Remove the IPA symbol TextFormField/IpaTextField (lines 167-173). Instead, add an IPA symbol lookup that maps feature combinations to IPA symbols. Create a helper map or function `_deriveIpaSymbol(String type, {String? manner, String? place, String? voicing, String? height, String? backness, bool? rounded})` that returns the standard IPA symbol for the selected feature combination.

Use the IPA data from the existing `ipa_data.dart` (Plan 03) to build this mapping. Each IpaSound in that data has symbol, manner, place, voicing (for consonants) and symbol, height, backness, rounded (for vowels).

Show the derived symbol as a prominent read-only display above or below the dropdowns: a large centered Text widget showing the IPA symbol (or "Select features..." placeholder if incomplete). Style it like a badge: large monospace font, ~32px, with a subtle surface container background.

Keep the _symbolController internally — populate it from the derived symbol when features change, so _save() still works with the same logic.

If the feature combination doesn't map to a known IPA symbol (custom/rare sound), show a fallback: a small "Custom symbol" text field appears below the display, allowing manual entry. This handles edge cases without making the common case harder.

**2. Add Latin/romanization TextFormField:**

Add a `_latinController` TextEditingController. In the dialog body, after the feature dropdowns (and after the derived IPA display), add:

```dart
const SizedBox(height: 16),
TextField(
  controller: _latinController,
  decoration: const InputDecoration(
    labelText: 'Latin representation',
    hintText: 'e.g. sh, th, ng',
  ),
),
```

Pre-fill from existing phoneme data if editing. Note: The Phoneme table in app_database.dart does NOT currently have a `latin` column. For now, store nothing in the database for this field (it is informational UX only). The actual romanization mapping is managed in the romanization section. Add a helper text below: "Tip: Full romanization rules are managed in the Romanization section below."

Actually, looking at the schema — the Phonemes table has no latin column and adding one would require a schema change + codegen. Instead, this field should look up and display the existing romanization mapping for this phoneme's symbol (read-only). Query the romanization DAO to find a mapping where `ipaSymbol == phoneme.symbol`. Display it as informational. If no mapping exists, show "No romanization defined" with a muted style. This avoids schema changes while giving the user the information they asked for.

**3. Add Delete button in dialog actions (when editing):**

When `_isEditing` is true, add a delete button to the dialog actions (left-aligned, before the spacer):

```dart
actions: [
  if (_isEditing)
    TextButton(
      onPressed: _saving ? null : () => _confirmAndDelete(context),
      style: TextButton.styleFrom(foregroundColor: colorScheme.error),
      child: const Text('Delete'),
    ),
  if (_isEditing) const Spacer(),
  TextButton(onPressed: ... child: Text('Cancel')),
  FilledButton(onPressed: ... child: Text('Save')),
],
```

The _confirmAndDelete method should call the existing `confirmDeletePhoneme` function (already at bottom of file), then close the dialog.

**4. Update inventory_page.dart:**

Remove the `onLongPress` handler from _PhonemeChip (line 481) since delete is now in the dialog. Keep the onTap to open PhonemeEditDialog.
