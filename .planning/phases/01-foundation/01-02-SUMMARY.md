## Decisions Made

- Used `DriftNativeOptions.databasePath` callback instead of `driftDatabase(name:)` default: the default writes `{appDocumentsDir}/{name}.sqlite` which cannot support per-project isolation at different directories. The `databasePath` callback lets us point each database to `{appDocumentsDir}/conlang/{projectId}/project.db`.
- `projectDatabase` family provider is synchronous despite `appDocsDirProvider` being async: uses `ref.read(appDocsDirProvider).value` to peek at the cached value after first resolution. The `LazyDatabase` inside `AppDatabase.fromPath()` defers actual file open, so even a stale/placeholder path on the first frame is safe. This avoids every consumer needing to handle `AsyncValue<AppDatabase>`.
- Empty state rendered inside AppShell (not via GoRouter redirect): keeps router structure clean, avoids redirect loop complexity, and matches the menu-bar-driven design decision from plan frontmatter.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] driftDatabase() API mismatch — path: parameter does not exist**
- **Found during:** Task 1 (AppDatabase.fromPath factory implementation)
- **Issue:** Initial implementation passed `path:` to `driftDatabase()` which only accepts `name:` + optional `DriftNativeOptions`. Dart analyzer reported `undefined_named_parameter`.
- **Fix:** Switched to `driftDatabase(name: 'project', native: DriftNativeOptions(databasePath: () async => absolutePath))` which correctly routes to the per-project path.
- **Files modified:** lib/db/app_database.dart
- **Verification:** dart analyze reports no errors
- **Committed in:** 5ed08eb (Task 1 commit)

**2. [Rule 1 - Bug] AsyncValue.valueOrNull does not exist in riverpod 3.0.3 — use .value instead**
- **Found during:** Task 1 (project_providers.dart, projectDatabase family provider)
- **Issue:** Initial code used `.valueOrNull` which is not defined on `AsyncValue<T>` in riverpod 3.0.3 (only `.value` which returns `T?`).
- **Fix:** Changed to `.value`.
- **Files modified:** lib/features/project/data/project_providers.dart
- **Verification:** dart analyze reports no errors
- **Committed in:** 5ed08eb (Task 1 commit)

**3. [Rule 1 - Bug] `_ = link` (keepAlive handle) is not valid Dart syntax for discarding a value**
- **Found during:** Task 1 (project_providers.dart, projectDatabase family provider)
- **Issue:** Attempted to suppress unused-variable lint on the keepAlive link by assigning to `_`, which is not a valid identifier in this context.
- **Fix:** Removed the keepAlive approach entirely. The provider lifecycle is managed by Riverpod's default eviction rules (provider is kept alive as long as there are listeners, which is correct for the family use case).
- **Files modified:** lib/features/project/data/project_providers.dart
- **Verification:** dart analyze reports no errors
- **Committed in:** 5ed08eb (Task 1 commit)
